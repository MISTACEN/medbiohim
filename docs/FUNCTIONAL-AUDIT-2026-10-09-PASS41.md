## Вывод
MEDBIOHIM находится в цикле **стабилизации и проверки интеграций**, а не в финальной приёмке и не в свободном добавлении функций. Приложение и основные предметные контуры уже существуют. При этом текущая производственная версия подтверждена только как готовое Vercel-развёртывание старого коммита; работа интерфейса и функций в браузере не была подтверждена.

## P1 — подтверждённая проблема конфиденциальности ответов тренажёра
Проверено чтение живых данных Supabase:
- 206 опубликованных карточек в `public.trainer_feed_cards`;
- все 206 содержат `correct` во вложенных объектах `question.options`;
- политика `trainer_feed_cards_anon_select` разрешает `anon` читать опубликованные строки; политика `trainer_feed_cards_authenticated_select` разрешает это `authenticated`;
- RLS включён, но действующая политика SELECT не скрывает ключ ответа внутри JSON.

Пути приложения также подтверждены исходниками:
- `backend/config/routes/platform.php` отдаёт поле `question` в ленте и карточке без удаления признака `correct`;
- `src/app/api/v1/[...path]/route.ts` в резервном Supabase-режиме выбирает и возвращает `question` целиком;
- клиентская модель `TrainerCard` тоже допускает поле `correct`.

Это не исправляется скрытием ответа в интерфейсе: значение уже находится в ответе API и доступно через Supabase Data API при текущих политиках. Следующее исправление должно быть согласованным: безопасная проекция карточек без ключей ответа, серверная проверка вариантов, безопасная запись результатов и отдельный RPC/серверный путь для fallback, плюс ограничение прямого чтения исходной таблицы. Перед изменением прав нужно проверить все пути сессии тренировки, чтобы не сломать старт, продолжение и сохранение результатов.

### CI сейчас не выполнил тесты
Повторный запуск code-check `37935997871` (attempt 2) снова завершился до первого шага: `runner_id=0`, пустой `runner_name`, `steps=[]`, логов нет. Публичная страница статуса GitHub на момент проверки отображает All Systems Operational; ранее 5 октября GitHub отдельно сообщал о деградации Hosted Runners. См. Workflow `.github/workflows/code-check.yml` вызывает `npm run predeploy:audit`, а скрипт включает TypeScript check, Next.js production build и PHP lint при доступном PHP CLI. Поэтому пока runner не запускается, эти проверки не получили нового результата.

### Vercel и браузер
Vercel сообщает `READY` для `medbiohim.vercel.app`, но metadata указывает на коммит `4c6fc5e`, а не на `fb4eed97`. Получить HTML текущего deployment через подключение не удалось из-за 403. Статус READY не считается доказательством работы логина, расписания, тестов, медиапутей и мобильной верстки.

### API-клиент
В `src/lib/api.ts` таймер создаёт собственный `AbortController`, однако запрос отправляется с `options.signal ?? controller.signal`. Когда вызывающий код передаёт свой signal, таймер не отменяет запрос. Следует объединить сигналы так, чтобы сохранялась и отмена вызывающего кода, и внутренний timeout.

### Качество проверок
- `eslint.config.mjs` содержит только `ignores`, активных правил линтера нет; скрипт `lint` сейчас не даёт полноценного контроля качества.
- `package-lock.json` отсутствует; predeploy-аудит сам выводит предупреждение о нерепродуцируемом разрешении диапазонов зависимостей.
- HTML материалов выводится через `dangerouslySetInnerHTML`; полноценная очистка сохранённого пользовательского/админского HTML в просмотренном пути не подтверждена. Это требует отдельной проверки и санитаризации, но само наличие API не доказывает эксплуатируемую XSS.

## Гистология, материалы и контент

### Электронограммы и физические файлы
В Supabase найдено 28 опубликованных электронограмм, у которых `source_key` не имеет соответствия в `content_sources.source_path`. В репозитории отсутствует ожидаемая папка с физическими изображениями. Это подтверждённое несоответствие метаданных; существование или отсутствие файлов на SpaceWeb/B2 не проверено. Править пути массово до сверки с физическим деревом нельзя.

### Вопросы и лекции
- В `exam_questions` найдено 466 записей гистологии, включая 366 опубликованных и 100 неопубликованных; обнаружены группы повторяющегося текста и записи без заполненного `answer`. Это кандидаты на сверку с исходниками, а не команда на удаление.
- Для гистологии существуют как минимум два источника лекций: 23 опубликованные записи в основном `site_content` и 17 записей в `histology_lectures`, все неопубликованные. Сначала нужно сравнить содержимое и привязки, затем назначить источник истины; не переносить/удалять записи вслепую.
- Проверки связей основного банка `questions` и `test_questions` ранее подтвердили отсутствие дубликатов связей и осиротевших привязок в проверенной выборке. Это не заменяет функциональный прогон начала/ответа/завершения теста.
- Не активировать автоматически неопубликованный тест эмбриологии из 67 вопросов: это решение о доступности, не доказательство повреждения данных.
- Не изменять существующие пять `ticket_banks` без отдельной необходимости.
