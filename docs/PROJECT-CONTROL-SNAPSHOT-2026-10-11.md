## 1. Продуктовая идея — зафиксировано

MEDBIOHIM — самостоятельная образовательная платформа для самоподготовки студентов к экзаменам, тестам, зачётам и занятиям. Это **не официальный сайт университета и не замена официальному порталу**. Принцип: «от студентов для студентов», в первую очередь для небольшой учебной группы; проект не позиционируется как коммерческий продукт.

Главные принципы:
- Сохранять уже одобренные структуру, навигацию и визуальный язык сайта; улучшать существующие страницы, а не создавать параллельные дубли.
- Дать студенту возможность самостоятельно изучать материалы, тренироваться, видеть ответы там, где это предусмотрено режимом подготовки, вести учебные дела и отслеживать собственный прогресс.
- Общие учебные данные (например, домашнее задание группы) отделять от индивидуального выполнения/сдачи студентом.
- Подтверждённые исходные вопросы и ответы, импортированные данные и AI-предложения должны различаться по происхождению. Не выдавать AI-генерацию или непроверенный материал за официальный.
- Автоматизация помогает студенту, но не должна незаметно выполнять действия от его имени или обходить авторизацию.
- Платные AI-вызовы не обязательны для базовой работы; использовать AI только там, где он действительно нужен и разрешён конфигурацией.

## 2. Технологии и размещение

- Frontend: Next.js; исходный код в GitHub, развёртывание сайта настроено через Vercel.
- Backend: PHP API, предназначенный для текущего хостинга SpaceWeb.
- База данных/авторизация: Supabase.
- Файлы/архивы: часть материалов находится в репозитории/content; изображения сайта также используют существующую структуру контента. Для больших файлов предусмотрено внешнее хранение; ранее настроен приватный Backblaze B2 bucket `medbiohim-files` с EU endpoint.
- Telegram: отдельный Node.js webhook-проект `integrations/telegram-bot` (предполагаемое отдельное развёртывание Vercel) и существующий PHP-сервис ingestion.
- GitHub Actions должны проверять frontend, backend, интеграции, smoke и формирование архивов, но на момент снимка runner не выполняет шаги.

Конфигурационные сведения/идентификаторы не являются секретами сами по себе, но ключи и токены нельзя помещать в документацию или логи. Никогда не фиксировать Telegram token, Supabase service-role key, пароль, секрет webhook или приватные URL с учётными данными в Git.

## 3. Что было изменено в последнем проходе

Изменения внесены непосредственно в `main`, без создания новой ветки. **Production-развёртывание, настройки живого Telegram webhook, секреты и production-база данных не менялись.**

### 3.1 PHP: fail-closed проверка секрета webhook

Добавлен `backend/src/Support/TelegramWebhookSecret.php` с проверкой, что ожидаемый и переданный секрет существуют и непустые, и сравнением через `hash_equals`. `backend/src/Services/TelegramHomeworkService.php` использует этот helper вместо старого поведения, при котором пустой конфигурированный секрет мог разрешать запросы.

Добавлен `backend/tests/TelegramWebhookSecretTest.php` с тестами отсутствующего/пустого ожидаемого секрета, отсутствующего/пустого предоставленного секрета, неверного и корректного значения. В `.github/workflows/code-check.yml` добавлен запуск этого теста.

**Не подтверждено:** фактическое выполнение PHP-теста, весь PHP lint/type/route/security аудит и поведение на живом backend — runner не запустил шаги.

### 3.2 Домашние задания: student-first создание

В `src/app/schedule/page.tsx` условие видимости создания домашнего задания в интерфейсе изменено на наличие авторизованного пользователя (`canCreateHomework = Boolean(user)`). В `backend/config/routes/homework.php` убрано требование, чтобы создатель обязательно был сотрудником или старостой. Предшествующая проверка академического контекста/группы оставлена.

Задуманное правило: любой авторизованный участник соответствующей группы может создать общее задание; чужой участник не должен иметь возможность создавать задание в этой группе. Общая запись задания не равна индивидуальной сдаче/отметке выполнения.

**Не подтверждено:** интеграционные тесты участника и постороннего пользователя; права на предмет/группу/расписание; прикрепление файлов; корректность отображения после записи. Это изменение исходников, а не доказательство сквозной работы.

### 3.3 Telegram: кнопка входа в существующий сайт

В `integrations/telegram-bot/lib/commands.js` команды `/start` и `/app` формируют Web App entry point с URL `MEDBIOHIM_APP_URL` (по умолчанию `https://medbiohim.vercel.app/`). В `integrations/telegram-bot/api/webhook.js` добавлена inline-кнопка Telegram Web App. В `integrations/telegram-bot/test/commands.test.js` добавлен тест URL. README описывает конфигурацию BotFather и webhook.

Это **только способ открыть текущий сайт внутри Telegram**. Кнопка не авторизует пользователя, не создаёт аккаунт и не связывает Telegram ID с существующей учётной записью.

### 3.4 Telegram: строгая проверка Mini App initData

Добавлен `backend/src/Support/TelegramWebAppInitData.php` и тест `backend/tests/TelegramWebAppInitDataTest.php`. Проверка предназначена для подписи Telegram Web App initData, свежести auth_date и структуры user payload. Последними изменениями усилена проверка ID: допускается положительный целочисленный ID, а не произвольное числовое значение; тесты дополнены пустым user, нечисловым, дробным, нулевым ID и слишком длинными/пустыми данными.

**Ограничение:** сам по себе helper не означает, что он подключён к endpoint регистрации/входа или что Telegram login уже существует. Сквозная регистрация/привязка не реализована и не проверена.

### 3.5 Telegram: пересылка групповых обновлений в PHP

В `integrations/telegram-bot/api/webhook.js` добавлен необязательный relay групповых сообщений:
- Telegram webhook должен указывать **только на Node endpoint**.
- Если задан `TELEGRAM_HOMEWORK_WEBHOOK_URL`, Node пересылает group/supergroup update на PHP по HTTPS.
- В запросе передаётся `X-Telegram-Bot-Api-Secret-Token` с `TELEGRAM_WEBHOOK_SECRET`.
- Неправильный URL и HTTP-ошибка не выдаются за успешную обработку.
- Если relay не настроен, обновление не пересылается; это не означает, что домашнее задание сохранено.

В `integrations/telegram-bot/test/webhook.test.js` добавлены тесты успешной пересылки и отсутствующей конфигурации; существующий тест групповых сообщений изолирован от внешней переменной relay. README дополнен правилами конфигурации и архитектурой единственного webhook.

**Не подтверждено:** Node unit tests, PHP приём обновления, распознавание задания, сохранение в БД, повторная доставка, идемпотентность, сопоставление чата с учебной группой, прикреплённые фото/документы, авторизация и мобильный end-to-end тест.

## 7. История и направление основных функций

### Тесты и вопросы
- Нужны режим подготовки с доступом к полному банку вопросов и правильным ответам (не только прохождение экзаменационного теста).
- Типы вопросов: одиночный выбор, несколько правильных ответов, свободный ответ, последовательный проход по всем вопросам, номера вопросов, редактирование администратором.
- AI-сверка свободного ответа должна быть необязательной, не учитывать орфографические ошибки, учитывать смысл вопроса и ответа; точное совпадение проверять без AI, если это достаточно.
- Жалоба на вопрос/ответ должна быть доступна там, где пользователь работает с вопросом, и попадать в управляемую очередь админ-панели.
- Импортированные реальные вопросы должны сохранять источник; AI-предложения помечать и проверять.
- Проверить старую схему вопросов, RLS, импорт в Supabase, доступы и фактическое число опубликованных вопросов.

### Расписание, задания, посещаемость
- Нужны виды недели/месяца/семестра, предметы и пары, добавление лекций, домашнее задание к дате/предмету и фото/вложения.
- Общая задача принадлежит учебной группе; индивидуальное выполнение/ответ каждого студента хранится отдельно.
- Посещаемость: был/уважительная причина/болезнь/неуважительная причина; прогресс и пробелы в знаниях.
- Все способы создания задания (вручную на сайте, Telegram, в будущем расширение) должны вести в один канонический workflow с правами, источником, дедупликацией и журналом.
- Староста/администратор не должны быть единственным источником общих заданий, если пользовательская модель требует самостоятельного ввода любым членом группы.

### Гистология, атлас и медиа
- Сохранить текущий дизайн атласа и центрирование изображения; не возвращать изображение к верхней части viewport.
- Полноэкранный просмотр, лупа, масштабирование/перемещение в любой точке, мобильный и desktop UX.
- Подписи и пояснения к препаратам должны сохраняться; схемы/таблицы лекций отображать читаемо.
- Сжатие медиа не должно уничтожать читаемость подписей; для видео сохранить качество, близкое к Full HD, где исходник позволяет.
- Ранее отмеченные данные гистологии: `subject_slug=histology`, `specialty_slug=mbh`, режим electronogram; не изменять уже имеющиеся 5 UUID в `ticket_banks`; 28 электронограмм; карточки тренажёра в `data/content_packages/histology-mbh-trainer-cards.json` (206 карточек по прошлой фиксации); не заменять старые вопросы новыми, а добавлять; маппинг тем к учебному плану начинать с 3-го семестра.
- Проверять медиа endpoint `GET /api/v1/trainers/feed/{id}/image`, `trainer_feed_cards.source_key`, `preparation.imagePath`, пути `backend/content/histology/`, `HISTOLOGY_MEDIA_ROOT`, aliases `5_Фотографии препаратов/...`, `electronograms/images/<slug>.png`, `em/<slug>.png`. Все конкретные пути перепроверить перед изменением.

### Telegram
- Два назначения: (1) безопасная регистрация/вход и открытие существующего сайта как Mini App; (2) извлечение домашних заданий из группового чата и прикреплённых медиа.
- Telegram Bot API бесплатен, но Vercel/Supabase/hosting имеют лимиты и условия, которые могут меняться. Не обещать безусловную нулевую стоимость, безлимитность или постоянную доступность.
- Telegram позволяет одному боту иметь один активный webhook; поэтому текущая схема: Telegram → Node webhook → (опционально) PHP relay. Не пытаться назначать один токен на два параллельных webhook.
- Для безопасной настройки нужны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_WEBHOOK_SECRET`, `MEDBIOHIM_APP_URL`, необязательный `TELEGRAM_BOT_USERNAME`, `TELEGRAM_HOMEWORK_WEBHOOK_URL`; на PHP стороне могут требоваться `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USER_ID` и тот же secret согласно текущему сервису. Проверить названия по текущему коду до настройки.
- Не включать AI как обязательную зависимость. Для неизвестных/неуверенных заданий — ручное подтверждение.

### Браузерное расширение / EIOS / внешние источники
- Пока это планируемый мост импорта, не готовая интеграция.
- Должно работать по явному действию пользователя, показывать preview перед импортом, сохранять источник и дату, обнаруживать дубли и версии, не хранить пароль EIOS и не обходить CAPTCHA/2FA/контроль доступа.
- Сначала аудит прав, источников и доступных сценариев; затем MVP только для пользователя, который имеет доступ и сам инициирует импорт.

## 8. Бесплатность и расходы

Цель — минимальная стоимость и работа без обязательного платного AI:
- Telegram Bot API: обычно без оплаты за базовое использование бота.
- GitHub Actions: зависит от доступности/лимитов и настроек аккаунта; сейчас основная проблема не стоимость теста, а runner, не исполняющий шаги.
- Vercel Hobby и Supabase Free имеют квоты и меняющиеся условия; проверить актуальные ограничения перед production.
- SpaceWeb — уже используемый PHP backend host; не считать его бесплатным без проверки текущего тарифа пользователя.
- Backblaze B2 имеет тарифные/операционные лимиты; не размещать большие архивы в Supabase, если они не помещаются в план.
- Платный AI API — только opt-in, с лимитом/отключением и понятным fallback.
- Никакие новые расходы, платные интеграции или производственные настройки в этом проходе не включались.
