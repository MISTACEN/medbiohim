# MEDBIOHIM Importer 1.3.0

Браузерное расширение (Manifest V3) для ручного сохранения материалов с публичного сайта ДВГМУ (`www.fesmu.ru`), ЕИОС ДВГМУ, NeoFamily Lab и Школы Сеченова в личную библиотеку MEDBIOHIM.

- Читает только открытую страницу и только по нажатию «Разобрать страницу».
- Показывает найденные ссылки; пользователь снимает лишние и подтверждает импорт.
- Ничего не отправляет автоматически, не хранит пароли и не обходит платный доступ.
- Сохраняет заголовок, ссылку, тип, источник, дату публикации и короткое описание.

## Что нового в 1.3.0

- **Карта источников `src/content/sources.json`** — селекторы, лимиты, правила типов и regex дат вынесены из кода в декларативный JSON. Редизайн платформы теперь правка одного файла: `selectors` источника дополняют `common` (массивы конкатенируются, строки заменяют). После правки поднимите `version` в JSON и `version` в `manifest.json`.
- **Перехват сетевых ответов (`interceptor.js`, режим `MAIN`, `document_start`)** — если платформа рисует список из собственного JSON, расширение подхватывает заголовки и ссылки из уже загруженных страницей ответов. Работает только пока пользователь смотрит превью: включается по «Разобрать страницу», выключается при закрытии превью, импорте или по TTL 100 с. Ничего не читает из cookies/заголовков/тел запросов, не трогает `login|auth|token|session` и кросс-доменные вызовы, ничего никуда не шлёт — только складывает пары `{title, url}` в превью с бейджем «сеть».
- Импорт пишется в приватную таблицу `imported_sources` (RLS: только владелец), старые ключи `site_content` читаются как legacy до разовой миграции.

## Что нового в 1.2.0

- Публичные страницы ДВГМУ (`www.fesmu.ru`) помечаются источником `fesmu` («ДВГМУ»), а не `eios`: это официальный сайт вуза, а не ЕИОС.
- Заголовок карточки читается из атрибутов `area-label` / `data-title` / `title` / `alt` — карточки Bitrix на `www.fesmu.ru` содержат пустую ссылку-картинку, из-за чего новости, объявления и расписание раньше не разбирались.
- Дата `дд.мм.гггг` из карточки сохраняется как `published_at`; несуществующие даты (`31.02.2026`) отбрасываются.
- Сопоставление хостов стало строгим: шаблон `fesmu.ru` больше не совпадает с чужими доменами вида `notfesmu.ru`.

## Сборка

```bash
cd browser-extension
npm ci
npm run build      # dist/
npm run package    # dist/ + ../public/downloads/medbiohim-importer.zip
```

`dist/` — распакованное расширение, `public/downloads/medbiohim-importer.zip` — архив для страницы `/extension`. CI workflow `deploy-browser-extension.yml` собирает проект, проверяет ссылки манифеста, пересобирает архив и загружает artifact.

## Установка

1. Скачайте архив со страницы `/extension` или возьмите `browser-extension/dist`.
2. Откройте `chrome://extensions`, включите режим разработчика.
3. «Загрузить распакованное» → выберите папку.
4. В попапе укажите адрес API (по умолчанию production Worker) и access token MEDBIOHIM, нажмите «Сохранить».

Токен хранится в `chrome.storage.sync` и отправляется только на указанный API.

## API

- `POST /api/v1/integrations/imports` — `{ items: [{ title, url, kind, source, summary?, published_at? }] }`, максимум 50.
- `GET /api/v1/integrations/imports` — свои записи.
- `DELETE /api/v1/integrations/imports/:id` — удалить свою запись.
- Алиасы для старых сборок: `POST /api/v1/integrations/fesmu/import`, `POST /api/v1/integrations/fesmu/dedup`.

Записи хранятся в `imported_sources` (`user_id` из JWT, RLS owner-only, дедупликация по `content_hash` = sha256(url)); дубликаты одного пользователя пропускаются. Legacy-ключи `site_content` `extimport:<user id>:<sha256(url)>` читаются и удаляются через тот же API до окончания разовой миграции.

## Структура

```
manifest.json                 MV3, хосты, разрешения, два content script (MAIN + isolated)
webpack.config.cjs            сборка background/popup/analyzer/interceptor
src/background/serviceWorker.js  отправка пакета в API, ретраи
src/content/analyzer.js       разбор DOM платформ + буфер сетевых находок
src/content/interceptor.js    перехват fetch/XHR в MAIN-мире (только JSON, только свой origin)
src/content/sources.json      карта источников: селекторы, лимиты, правила типов
src/js/popup.js               настройки, превью, выбор, импорт
src/popup/popup.html          интерфейс попапа
scripts/package.mjs           ZIP без внешних зависимостей
```

## Карта источников

`sources.json` описывает то, что раньше было зашито в `analyzer.js`:

| Ключ | Смысл |
|---|---|
| `common.anchor_scope` | CSS-селектор ссылок-кандидатов |
| `common.heading_scope` | заголовки, из которых тоже собираются ссылки |
| `common.card_selector` | обёртки карточек (для заголовка, описания и даты) |
| `common.title_attributes` | атрибуты, где лежит настоящий заголовок (Bitrix `area-label`) |
| `common.summary_selector` | где искать короткое описание |
| `common.placeholder_titles` | «заголовки»-заглушки, которые отбрасываются |
| `common.date_pattern` | regex даты публикации `дд.мм.гггг` |
| `common.skip_url` | расширения файлов, не являющихся материалом |
| `common.kind_rules` | правила `document`/`event`/`announcement`/`topic` по порядку |
| `common.limits` | пределы длины заголовка/описания и число ссылок |
| `sources[]` | `id`, `label`, `match` (regex хоста) и `selectors`-оверрайды |

## Ограничения

- Селекторы страниц ориентированы на публичную разметку; при редизайне платформы правится `sources.json`, а не код.
- Импорт не создаёт вопросы или тесты — это ссылки в личной библиотеке.
- Перехват видит только те JSON-ответы, которые страница запросила сама, пока превью открыто; если список отрисован на сервере, работает DOM-разбор.
- Расширение не авторизуется на платформах, не хранит их пароли и не обходит платный доступ.
