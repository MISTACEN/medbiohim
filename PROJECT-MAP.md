## Как устроен проект (30 секунд)

Это **модульный монолит** из 4 слоёв. Каждый учебный домен (тесты, лекции, предметы, расписание, кабинет преподавателя…) повторяется на каждом слое с одним и тем же именем:

```
Браузер
  src/app/<домен>/            → страница (маршрут) — тонкая точка входа
  src/components/<домен>/     → интерфейс домена
  src/lib/api/<домен>.ts      → клиент API (fetch-обёртки, типы)
  src/lib/endpoints.ts        → ЕДИНСТВЕННОЕ место со строками путей /api/v1/*
      ↓ same-origin /api/v1/*
  src/app/api/v1/[...path]/route.ts  → прокси Vercel → Cloudflare
      ↓
  workers/api/src/routes/<домен>.ts  → серверная логика + проверка прав
      ↓
  supabase/migrations/        → схема БД + RLS; Supabase — источник истины
```

**Правило навигации:** ищешь «расписание» — смотри `src/app/schedule`, `src/components/schedule`, `workers/api/src/routes/schedule.ts`. Всё.

## Мутные места (честно)

1. **`chem/` vs `chemistry/`** — два компонентных каталога (историческое); химию ищи в обоих.
2. **`builder/` vs `constructor/`-наследие vs `editor/`** — конструктор контента и редактор лекций — разные вещи.
3. **`tests/` vs `tickets/` vs `practice/` vs `cards/`** — три входа в один тестовый движок (подготовка/билеты/практика).
4. **Права в двух местах**: `src/lib/admin/access.ts` (легаси-проверка Admin UI) и `src/shared/permissions` (новая модель) — клиентские дубли, сервер один (`permissions.ts` воркера).
5. **`src/core/` не выделен физически** — auth в components, права в shared, api-клиент в lib. Это осознанная цель, не сделана.
6. **70 файлов роутов воркера** — кабинет уже в подпапке routes/teacher/ (образец разнесения); остальные домены ищутся по имени файла. Следующие кандидаты: admin.ts (1445 строк — telegram+lectures+questions+users+files в одном; сейчас в работе у второго агента), workshop.ts (787), admin-parity.ts (680).
7. **Страницы-монолиты фронтенда**: schedule/page.tsx (1221), subjects/[id]/page.tsx (1084, 40 импортов), settings/page.tsx (869), page.tsx (836), practice/page.tsx (829) — при доработке этих разделов выносить крупные куски в src/components/<домен>/.

## 👥 Матрица полномочий по ролям (утверждено владельцем 2026-11-07)

Проект остаётся студенческим: независимость от преподавателей — базовые функции работают, даже если ни один учитель не подключён.

### 👤 Студент
- Личное: задания (сам добавляет своей группе), заметки, карточки, закладки, материалы, сессии, планировщик, прогресс — всё приватно
- Обучение: предметы → темы → лекции/тесты/тренажёры/атласы; билеты; отработки; калькуляторы; AI-тьютор
- Workshop: публикация своих материалов (по умолчанию публично, режим модерации переключается)
- Сообщество, поиск, настройки, Telegram-привязка
- ❌ Никогда: чужие результаты, админ-функции, чужие группы

### 🎖 Староста (в пределах СВОЕЙ группы)
- Всё, что студент, плюс:
- Состав группы: добавление по email, подтверждение заявок
- Поток/подгруппы, ручная правка семестра группы
- Публикация ДЗ группе; Smart Paste (вставка текста ДЗ из Telegram-чата с разбором на дату/тему/чек-лист)
- Курирование материалов группы, загрузка журналов (когда OCR будет реализован)
- ❌ Не может: менять курс/год поступления (только запрос админу), видеть индивидуальные результаты других студентов, админ-функции

### 🛡 Модератор (на уровне сайта)
- Всё, что студент, плюс:
- Workshop-модерация: одобрение публикаций для других групп, скрытие при жалобах
- Слияние дубликатов тем, перепривязка тестов
- Платформенный контент: банк вопросов, варианты, лекции (вместе с админом)
- ❌ Не может: индивидуальные результаты студентов, роли, глобальные параметры, доступы к разделам

### 👨‍🏫 Преподаватель (добровольный участник, временная замена официального портала)
- Навигация: только Главная + Кабинет /teacher + личные настройки — студенческие разделы скрыты И закрыты на сервере (403)
- Единственное исключение: авторский preview своего теста (/tests/preview) — проверить глазами студента
- Свой контент: лекции (научный редактор), личный банк вопросов, тесты (сборка из банка), файлы
- Тесты: настройка (дедлайн/время/попытки/число вопросов), назначение группам ↔ отдельным студентам, снятие
- Проверка: авторский preview (без статистики), сводка по группе, карточки студентов (ФИО, попытки, %), аналитика по вопросам (свои/подключённые тесты), CSV-ведомость, детализация 1–4
- Открытые ответы: НЕ проверяет вручную — нейросеть последняя инстанция
- ❌ Никогда: Workshop, Admin, ACL, системные настройки, чужие группы/материалы/результаты, ручные роли

### 🔑 Администратор
- Всё вышеперечисленное плюс:
- Пользователи и роли; назначение учителей (группы/студенты/предметы/детализация)
- Группы: курс, поток, состав, глобальный каталог предметов/тем
- Доступы к разделам (Access Control: user/group, allow/deny, сроки, журнал)
- Контент платформы: тесты, билеты, лекции, материалы, банки; импорт
- Инфраструктура: расписание, SQL-консоль, аудит, api-logs, состояние Supabase/Worker/хранилища
- Финальное удаление, системные настройки
- ❌ Не показывает секреты/токены в интерфейсе
