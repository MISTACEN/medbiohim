## Как устроены строки

- `tests`: `test_key = chem-part1-theme-<тема>`, заголовок
  «Химия · Часть I · Тема 3.8. Альдегиды и кетоны», `subject_key =
  chemistry_organic_physical`, `is_published = false` (черновик).
- `questions`: `question_key = chem-part1-<тема>-<номер>`, `type` — `mcq` или
  `open`, `options` — JSON `[{label, correct}]` (для open — `[]`), `answer` —
  текст верного варианта; для последовательностей — через `→`.
- `test_questions`: связь по ключам, `order_index` внутри темы.

Темы сборника (1.1 … 3.13) — это тесты, а не темы платформы: `module_key` и
`topic_key` пустые, потому что в проекте нет справочника тем с такими слагами.
Вопросы лягут на предмет, без привязки к модулю/теме.

## Что не выгружено и почему

**Соответствия — 207.** Шаблон импорта знает только `mcq/open/problem/theory/
practical`; пар «слева — справа» в нём нет. Разложить каждый пункт в отдельный
mcq можно, но тогда формулировка вопроса искажается (в сборнике один вопрос —
это набор из 2–5 пар). Нужно решение по формату: либо добавить в импортёр тип
`match`, либо превратить пары в mcq вручную. Разбивка по темам: 1.1 — 18,
3.8 — 25, 3.10 — 24, 3.5 — 16, 3.9 — 16, 3.7 — 15, 3.4 — 13, 3.13 — 12,
3.1 — 10, 3.12 — 10, остальные меньше.

**mcq без ключа — 29.** Парсер вытащил в ответ сноску со страницы вместо номера
варианта, например у 1.1 №50: «2 Структурные формулы к заданиям 2, 4, 5…
(вырезаны из скана)». Верный вариант неизвестен, поэтому вопрос не импортируется
как mcq. Больше всего: 3.4 — 4, 3.5 — 4, 3.13 — 4, 1.4 — 2, 3.3 — 2, 3.8 — 2,
3.9 — 2, 3.10 — 2, остальные по одному. Их можно поправить по скану и дослать
отдельным файлом.

**Похожие на существующий банк — 10.** Точных совпадений с локальными
источниками (`public/content/portals/ticket-banks/organic_chemistry.json`,
`docs/orgchem-import/micro/`) нет, 10 вопросов тем 3.12 и 3.13 близки к банку
билетов. Живой банк в Supabase отсюда не виден, поэтому дедупликацию против
него нужно делать на сервере или с доступом к БД.

## Блокеры перед импортом

1. **Неоднозначный subject_key.** Импортёр ищет предмет по slug/имени и требует
   ровно одну строку (`subject mapping ambiguous or missing`). По документации
   проекта у `chemistry_organic_physical` в БД три активные строки — импорт
   упадёт. Сначала нужно схлопнуть дубли предмета или научить импортёр
   принимать UUID.
2. **Черновик.** `is_published=false`: после импорта тесты не появятся у
   студентов, пока их не опубликуют осознанно.
3. **Лимит 500 строк** учтён нарезкой; загружать файлы нужно по одному.

## Порядок импорта (когда будет разрешение)

1. `/admin/content-import` → выбрать `chem-part1-01.xlsx` → «Проверить файл».
2. Если ошибок нет — «Импортировать», затем повторить для 02 и 03.
3. Проверить в `/tests`, что темы появились, вопросы открываются, ключи
   совпадают с бумажным сборником.

Не проверено: сам импорт (нет разрешения и доступа к БД), сверка с живым банком,
публикация тестов.
