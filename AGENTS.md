# MEDBIOHIM — правила для ИИ-агентов

Эти правила обязательны для любого агента и субагента, работающего в репозитории.

## Источник истины
- Перед задачей прочитай этот файл и соответствующую инструкцию из `.agents/`.
- Сверяйся с текущим `main`; документы с датой — снимки, а не гарантия текущего состояния.
- Актуальная схема: `docs/ARCHITECTURE.md`, `docs/WORKERS-TOPOLOGY.md`, `docs/CURRENT-STATE-2026-11-03.md`. Для API parity и БД используй профильные аудиты из `docs/`.
- Не считай регистрацию маршрута, наличие binding или записи в БД доказательством рабочего пользовательского сценария.

## Git и параллельная работа
- `main` — основная ветка. Не создавай постоянные ветки, PR или отдельные ветки на каждую задачу без прямого разрешения пользователя.
- Несколько агентов не редактируют один рабочий каталог и один файл одновременно. Каждый исполнитель работает в отдельном worktree/контейнере/patch workspace.
- Субагенты возвращают patch/diff, список файлов, тесты и риски координатору. Только координатор интегрирует патчи в общий checkout, по одному, после проверки актуального HEAD.
- Перед записью проверь, что HEAD не изменился с момента подготовки патча. При конфликте — остановись и перебазируй/пересобери patch; не перезаписывай чужую работу.
- Не force-push, не reset --hard, не переписывай историю. Коммит в `main` — только после QA и разрешения задачи/пользователя.

## Безопасность и данные
- Никогда не читать, печатать, коммитить или пересылать значения секретов, токенов, cookies, service-role keys и приватные пользовательские данные.
- Не выполнять destructive SQL, массовые миграции, очистку данных, изменение RLS, production secrets, Worker bindings, DNS или deployment без отдельного разрешения.
- Supabase — canonical source of truth. Все пользовательские запросы должны быть ограничены авторизацией/RLS; service role только на сервере и только для обоснованного узкого сценария.
- Не помещать секреты в frontend env с префиксом `NEXT_PUBLIC_`, логи, фикстуры или инструкции.
- Не использовать legacy PHP/SpaceWeb как production API. Не направлять обычный трафик на `medbiohim-api-shadow`.

## Границы проекта
- Frontend: Next.js App Router в `src/app/`, UI в `src/components/`, клиентские библиотеки в `src/lib/`, статический контент в `public/` и `src/data/`.
- Canonical API: `workers/api/` (Hono/Cloudflare). Telegram Worker — `integrations/telegram-bot-cloudflare/`.
- БД/миграции: SQL-файлы в `database/migrations/`, `backend/database/migrations/`, `supabase/migrations/` — исторически несколько каталогов; сверять ledger, не запускать всё подряд.
- Legacy: `backend/`, `integrations/cloudflare-api/` и старые скрипты не менять без явной задачи.
- Хранилище: общий B2→Upstash adapter в `workers/api/src/lib/b2.ts`; trainer/histology media имеет отдельный resolver в `workers/api/src/routes/trainers.ts` (Drive index → Blob/SDK).

## Definition of done
1. Изменения соответствуют назначенному ownership и не затрагивают чужие области.
2. Добавлены/обновлены тесты; выполнены релевантные lint/typecheck/test/build.
3. QA проверил security, API compatibility, RLS и regression impact.
4. В отчёте указаны commit/base SHA, изменённые файлы, команды и результаты проверок, незапущенные проверки и риски.
5. Документация и roadmap обновлены только если изменилось фактическое состояние; не отмечать deployment/production acceptance без доказательства.
