# MEDBIOHIM — Media Quality & Delivery Policy

> Зафиксировано: 2026-10-07. Дополнение к Media Optimization Pipeline в ROADMAP.md и PHASES_STATUS.md.

## Главный принцип

Оптимизация медиа не должна ухудшать учебную ценность материала.

Правило:
**сначала читаемость/детали и совместимость, затем экономия размера.**

Если оптимизированная версия визуально заметно хуже исходной или теряет важную информацию, она не становится основной версией автоматически.

## Content-aware compression — обязательное правило

Pipeline **не должен использовать один глобальный параметр качества для всех файлов**.

Перед выбором derivative изображение классифицируется хотя бы ориентировочно:
- обычная фотография;
- микропрепарат/ЭМ/атлас с мелкими деталями;
- схема/диаграмма;
- скан/страница документа;
- text-heavy изображение с подписями;
- смешанный материал: фото + текст/обозначения.

Для материала с текстом, формулами, подписями, стрелками и мелкими обозначениями читаемость текста является отдельным quality gate и может иметь более высокий приоритет, чем дополнительная экономия размера.

### Multi-candidate selection

Для значимых изображений pipeline должен уметь создавать несколько кандидатов с разной степенью сжатия/разрешением:

**Original → анализ → high-quality candidate → optimal candidate → compact candidate → quality/readability check → лучший допустимый derivative.**

Алгоритм выбора:

1. Сначала определяется допустимый минимум качества для класса материала.
2. Для нескольких уровней сжатия проверяются размер и визуальная пригодность.
3. Проверяются мелкий текст, подписи, границы, тонкие структуры, артефакты и возможность zoom.
4. Выбирается **самый маленький кандидат, который проходит quality gate**.
5. Если optimal/compact не проходит — выбирается менее сжатый вариант.
6. Если ни один derivative не проходит — **используется original**.
7. Original никогда не удаляется только ради экономии места, если он нужен для восстановления качества/zoom/архива.

То есть цель:
**минимальный вес при сохранении читаемости и учебной детализации**, а не минимальный вес любой ценой.

Если автоматическая проверка качества не может надёжно подтвердить читаемость, pipeline должен предпочесть более качественный вариант, а не рискнуть потерей текста.

## Изображения

### Учебные фотографии, микропрепараты, ЭМ, атлас

- Не допускать агрессивного JPEG/WebP-сжатия, которое уничтожает мелкие структуры, подписи, границы клеток или диагностические детали.
- Не уменьшать разрешение ниже уровня, необходимого для нормального просмотра на Full HD/Retina и увеличения.
- Для крупных исходников генерировать responsive-варианты, а не одну маленькую копию.
- Основной формат оптимизированного изображения: WebP; AVIF — если качество/размер лучше на реальном материале.
- Всегда сохранять возможность показать более качественный вариант/оригинал для материалов, где важен zoom.
- Для схем, текста, сканов и формульных изображений использовать отдельную стратегию: lossless/near-lossless или исходный формат, если lossy compression ухудшает читаемость.
- Удалять только ненужные EXIF/GPS-данные; не удалять учебные подписи, встроенный текст или полезные metadata.
- Качество подбирается по классу материала, а не одной глобальной настройкой.

### Контроль качества

Перед публикацией derivative:

1. сравнить размер;
2. сравнить исходное и оптимизированное изображение;
3. проверить мелкие детали и текст;
4. проверить zoom;
5. проверить iPhone/Android/desktop;
6. если качество ниже заданного порога — использовать менее агрессивное сжатие;
7. если ни один derivative не проходит порог — использовать original.

Целевой результат: **максимальное уменьшение веса при отсутствии заметной потери читаемости**, а не минимальный размер любой ценой.

## Видео

### Full HD — обязательная возможность

Если исходное видео имеет 1920×1080 или выше, pipeline не должен автоматически превращать его в низкое разрешение.

Минимальная целевая лестница для исходника Full HD:
- 1080p — основная качественная версия;
- 720p — дополнительная адаптивная версия;
- ниже 720p — только как fallback для очень слабой сети/устройства, если это действительно необходимо.

Если исходник выше Full HD, допускается сохранение/транскодирование 1080p как основной веб-вариант, а более высокого оригинала — отдельно, если он нужен для архива/монтажа/обучения.

### Плеер

Плеер должен:
- поддерживать adaptive quality;
- позволять пользователю выбрать качество вручную, включая **1080p Full HD**, когда оно доступно;
- автоматически выбирать качество по сети/устройству;
- не путать качество источника и фактически доступные derivatives;
- корректно переключаться между 1080p/720p и fallback;
- сохранять нормальное управление на iPhone, Android и desktop;
- не заставлять пользователя скачивать оригинальный тяжёлый файл ради просмотра.

### Видео-кодеки

WebM/VP9/AV1 используются как оптимизированные варианты только после проверки реального выигрыша.

Для совместимости допускается параллельный fallback в широко поддерживаемом формате (например, MP4/H.264), если это требуется браузерами/устройствами.

Оригинал видео не должен удаляться только потому, что создан WebM-derivative.

## Размеры и качество

Pipeline должен учитывать:
- MIME и реальные codec/container;
- width/height;
- bitrate;
- duration;
- file size;
- checksum;
- наличие текста/схем/мелких деталей;
- назначение: preview, учебный просмотр, zoom, архив;
- класс визуального материала и выбранный quality profile;
- результат quality/readability gate для каждого candidate.

## Storage / delivery

Каноническая модель:

**Original → optimized master → responsive derivatives → client**

Supabase хранит metadata и связи; SpaceWeb/B2 — физические объекты.

Для derivatives:
- immutable naming/versioning;
- долгий cache;
- повторная генерация без потери связи с original;
- checksum для deduplication;
- source_file_id / asset family для связи вариантов;
- сохранение данных о качестве/классе/прошедшем quality gate.

## Failure policy

Если optimizer/transcoder недоступен:
- upload не должен ломаться без необходимости;
- поддерживаемый original сохраняется;
- UI показывает состояние processing/fallback;
- derivative может быть создан позже;
- ошибка оптимизации не должна приводить к потере пользовательского файла;
- если quality gate не может подтвердить безопасное сжатие, используется более качественный derivative либо original.

## Acceptance gate

Media Optimization считается DONE только после проверки реальных MEDBIOHIM материалов:

- фотографии препаратов;
- электронограммы;
- atlas images;
- лекционные изображения;
- PDF/DOCX с формулами/мелким текстом;
- минимум одно видео 1080p.

И проверки:

**original vs optimized → candidate selection → size → visual quality → text readability → zoom → 1080p playback → mobile/desktop → fallback → HTTP delivery.**
