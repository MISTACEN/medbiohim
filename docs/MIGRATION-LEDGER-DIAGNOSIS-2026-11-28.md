# Расхождение ledger миграций Supabase (диагностика 2026-11-28)

Проверка `Supabase Preview` в CI падает с «Remote migration versions not found in
local migrations directory». Это не ошибка кода: разошлись записи о применённых
миграциях и файлы в репозитории.

## Замер (read-only, скрипт `scripts/check-migration-ledger.mjs`)

| Метрика | Значение |
|---|---|
| Версий в `supabase_migrations.schema_migrations` | **170** |
| Файлов `database/migrations/YYYYMMDDHHMMSS_*.sql` | **60** |
| Версий в базе, которых нет файлом | **168** |
| Файлов, которых нет в ledger | **58** |

То есть в базе записаны 168 миграций, которых в репозитории нет как файлов
(применялись раньше, файлы переименованы/удалены), а 58 локальных файлов никогда
не отмечались в ledger (применялись вручную).

## Почему CI падает

`supabase migration list`/preview сверяет локальный каталог с ledger и требует,
чтобы версии совпадали. При таком расхождении он не может построить план и
завершается ошибкой — при этом на прод-базу это не влияет: схема уже применена.

## Варианты (по возрастанию риска)

1. **Оставить как есть, отключить Supabase Preview** как обязательный чек.
   Ledger — историческая запись; прод живёт, миграции применяются вручную.
   Минус: нет автоматического контроля.
2. **Repair ledger под фактическое состояние**: `supabase migration repair
   --status applied <версии>` для локальных файлов, которые точно применены;
   для 168 «сиротских» версий — `--status reverted` только если уверены, что их
   объектов нет (иначе это ложь в ledger).
3. **Восстановить файлы** для сиротских версий из истории git и привести каталог
   к 1:1 с ledger — самый честный, но объёмный путь: 168 файлов.

## Рекомендация

Порядок: (2) для 58 локальных файлов, затем (3) восстановление отсутствующих
файлов из истории — по мере надобности. Пункт (1) — временная мера, если CI
нужен зелёным прямо сейчас.

Скрипт только читает: `node scripts/check-migration-ledger.mjs` (нужен `pg` и
`DB_URL` в `.env.local`; пароль не печатается).

## Выполнено 2026-11-28: repair

`node scripts/repair-migration-ledger.mjs --apply` — 58 локальных файлов
отмечены применёнными (только строки ledger: `version`, `name`; DDL не
выполнялся). Перед записью снят бэкап прежнего ledger — `data/ledger-backup.json`.
Транзакция + `ON CONFLICT DO NOTHING`: повторный запуск безопасен, откат —
удалить эти версии или восстановить строки из бэкапа.

Проверка после записи:

```
remote: 228, local: 228, remote_only: 0, local_only: 0
```

То есть обе стороны сошлись ровно; жёсткая ошибка Supabase Preview
(«Remote migration versions not found in local migrations directory») больше
не воспроизводится.
