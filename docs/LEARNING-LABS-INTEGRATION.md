# Ветка `feat/portal-integrations-learning-labs` — что изменилось и как синхронизировать

## Принцип, вокруг которого всё построено

Один учебный инструмент = одна реализация (`slug`/`id` → один маршрут и один
ключ прогресса) и множество предметных контекстов. Инструмент открывается из
любой дисциплины, где он содержательно применим, с передачей контекста
(subject + topic) query-параметрами. Копий под предметы не появляется:
каталог `src/lib/sim/catalog*.ts` и реестр `src/lib/learning/modules.ts` —
единственные источники истины.

## Что уже было в main (опора, не дубликат)

- `src/lib/learning/` — единый реестр модулей: предметные области (включая
  дисциплины без slug: биохимия, фармакология, генетика, биофизика —
  резолв по slug, точному названию и префиксам), уровни применимости 1–3,
  межпредметные связи с темами, `moduleHref` (контекстная ссылка), прогресс.
- `src/lib/sim/` — data-driven движок симуляций: новая модель — это объект
  `SimDefinition` с чистой `compute()`, плеер общий для всех дисциплин.
- Встраивание в страницу предмета (`SubjectModules`, `SubjectSimulations`)
  и связь модулей с темами программы (`topicLinks`).

### Инструменты (новые маршруты)
- `/tools/punnett` — решётка Пеннета (`src/lib/genetics/punnett.ts` — чистая
  логика + `PunnettTrainer`).
- `/chemistry/balance` — балансировка реакций (`src/lib/chemistry/balance.ts`:
  парсер формул со скобками и ионами, метод Гаусса над точными дробями,
  проверка атомов и заряда; оговорка «баланс ≠ доказательство протекания»).

### Конструкторы и контракт прогресса
- `/constructors` — создание материалов без AI: флеш-карточки (База),
  чек-лист (Алгоритм), таблицы, пошаговые разборы; черновики в localStorage,
  предпросмотр, экспорт/импорт JSON (`src/lib/constructors/`). Центральная
  админ-панель не тронута.
- `database/migrations/20261104_module_tool_progress.sql` — аддитивная
  миграция контракта прогресса (`module_id`, `tool_id`, `subject_id`,
  `topic_id`, `launch_context`, `completion_status`, `progress`, `result`,
  `last_opened_at`). **Не применять на production без согласования** —
  контракт для планировщика.

## Синхронизация с актуальным `main`

1. `git fetch origin && git rebase origin/main` в ветке (или merge по
   политике репо — ветка не мержится самостоятельно).
2. Конфликтных с центральной системой интерфейсов нет: главная страница,
   планировщик, навигация, Telegram и админка не менялись. Изменённые
   существующие файлы — только `src/lib/sim/catalog.ts` (конкатенация
   каталогов), `src/lib/learning/modules.ts` (мерж связей + `TOOL_MODULES`),
   `src/lib/__tests__/sim-engine.test.ts` (обновлён список каталога).
3. Перед merge: `npx vitest run --project unit` и `npm test`
   (`test/status-tokens.test.mjs` падает на `main` до ветки — offenders в
   `src/app/page.tsx` и `src/app/subjects/page.tsx`, к ветке не относится).
4. Применить `database/migrations/20261104_module_tool_progress.sql` отдельным
   согласованием (аддитивная, повторный запуск безопасен).

## Известные ограничения

- Читалка электронного каталога ФЕсМУ остаётся в режиме библиографических
  карточек с официальным переходом (`src/lib/libraryExternal.ts`) — обход
  авторизации/DRM не предполагается по заданию.
- β-окисление/ЦТК считают консервативные P/O (2.5/1.5) — альтернативные
  значения указаны в `limitations` моделей.
