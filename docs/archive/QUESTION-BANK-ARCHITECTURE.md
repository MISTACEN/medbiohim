# Архитектура банков вопросов MEDBIOHIM

Обновлено: 2026-10-07

## Главное правило

**Каждый учебный предмет имеет собственный независимый банк вопросов и собственный набор тестов.**

Нельзя смешивать вопросы, ответы, темы или тесты разных предметов в одном предметном контексте.

## Предметный контекст

При открытии базы из страницы конкретного предмета передаётся его `subject_slug`.

Примеры:

- Гистология → `subject_slug=histology`
- Органическая и физическая химия → соответствующий slug химического предмета

В результате:

`Предмет → База вопросов → только вопросы этого предмета`

Если пользователь напрямую открыл общую базу без предметного контекста, ему разрешён ручной выбор предмета.

## База вопросов ≠ тест

База вопросов предназначена для изучения:

- просмотр полного опубликованного банка;
- просмотр вопроса;
- просмотр правильного ответа;
- поиск;
- фильтрация;
- пагинация;
- просмотр по темам/предмету;
- сообщение об ошибке.

Открытие вопроса в базе **не создаёт test_attempt**, preparation session, результат или изменение прогресса.

Тест предназначен отдельно для проверки знаний:

- создаётся попытка;
- ответы сохраняются;
- выполняется проверка;
- рассчитывается результат;
- история прохождения сохраняется.

## Жалобы

У каждого вопроса должна быть возможность:

**Сообщить об ошибке → конкретный question_id → жалоба → администратор → исправление вопроса/ответа.**

Жалоба не должна быть привязана только к тестовой попытке: пользователь может сообщить об ошибке непосредственно из базы вопросов.

## Изоляция

При просмотре гистологии:

- показываются только вопросы гистологии;
- показываются только тесты гистологии;
- темы принадлежат гистологии;
- ответы принадлежат вопросам гистологии.

При просмотре химии — аналогично только химический банк.

То же правило применяется ко всем будущим предметам.

## Правило хранения

Банк вопросов является предметным и должен иметь однозначную связь с предметом через канонический `subject_id/subject_slug`.

Нельзя определять принадлежность вопроса предмету только по названию, тексту вопроса или случайному совпадению темы.

## Регрессия

Любое новое API или UI для вопросов обязано проверять:

1. предметный контекст;
2. отсутствие cross-subject выдачи;
3. корректность правильного ответа;
4. отсутствие создания попытки при обычном просмотре;
5. корректную привязку жалобы к `question_id`.

Это постоянное архитектурное правило проекта.
