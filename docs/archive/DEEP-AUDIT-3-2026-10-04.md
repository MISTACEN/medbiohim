# MEDBIOHIM — DEEP AUDIT 3 / 2026-10-04

## Цель

Третий проход искал не только явные TODO/stub, а:
- функции, для которых UI-следов нет;
- backend routes, которые были shadowed/doubled;
- route handlers, которые были сломаны уже на уровне синтаксиса;
- frontend API helpers без consumers;
- legacy source trees;
- ложные fallback и silent-success;
- UI страницы, которые выглядят как раздел, но фактически являются alias/redirect;
- реальные проблемы в Supabase data model;
- расхождения между main, Vercel и SpaceWeb.

## Что обнаружено и уже исправлено

### 1. Shadowed backend routes

Удалены/сведены:
- legacy `/api/v1/schedule` PUT;
- legacy `/api/v1/admin/schedule/local`;
- duplicate `/api/v1/admin/import/schedule`;
- duplicate domain detail handlers from `domain.php`;
- duplicate `/materials`, `/community/posts`, `/progress` from `platform.php`;
- legacy trainer catalog routes;
- legacy admin compatibility routes;
- legacy TutorService route.

### 2. Реальный синтаксический дефект domain.php

В процессе удаления shadowed routes автоматическое удаление оставило обломки closure. Это было поймано GitHub PHP syntax check.

`domain.php` полностью переписан в чистую форму с только уникальными маршрутами:
- GET /groups
- POST /groups
- GET /subjects
- GET /subjects/{id}/gradebook
- POST /subjects

Backend syntax после восстановления: PASS.

### 3. Скрытый broken endpoint

`POST /admin/lectures/assist` существовал, но frontend consumer отсутствовал, а отдельного `LectureGeneratorService::assist()` в текущем сервисе не было.

Endpoint удалён как broken legacy surface.

### 4. SearchParams build-risk

`settings/page.tsx` и `admin/database/page.tsx` использовали `useSearchParams()` только для простых query-параметров.

Это было заменено на чтение `window.location.search` в client effect, чтобы не вносить лишнюю зависимость от Suspense/static rendering.

### 5. Admin content validation

Добавлена проверка:
- published test without questions;
- orphan test_question;
- orphan question link;
- material without source key;
- material pointing to missing active file;
- published trainer card without image path;
- MC/MCQ/case exam question without answer.

Важно: открытые билетные вопросы без `answer` не считаются дефектом. Live DB показала, что 703 таких записи — это ожидаемые `type=open` ticket questions.

## Что осталось реально недоделанным

### P1 — внешняя среда

1. **Vercel production lag**

Текущий production deployment всё ещё указывает на старый main commit `6dc8db...`. Текущий GitHub main уже намного новее.

Следствие: часть последних исправлений пока не считается production-delivered.

2. **SpaceWeb deployment**

GitHub workflow существует и проверяет backend, но из-за частых последовательных commits deployment runs могут отменяться/стоять в очереди. Нужен один финальный green commit и один успешный deploy run.

3. **Histology media**

Кодовая часть маршрута есть. 404/502 остаются только для физически отсутствующих/недоступных media объектов. Это требует SpaceWeb/B2 media smoke-test с реальными файлами.

4. **AI**

Backend chain существует, но runtime credentials/provider availability остаются внешней зависимостью. Нельзя считать AI production-ready только по наличию кода.

### P2 — продуктовые улучшения

1. Generic document viewer для всех subject materials.
Сейчас:
- HTML material читается inline;
- signed original URL доступен;
- histology имеет отдельный DOCX viewer.
Для любого DOCX/PDF вне histology нет единого полноценного viewer.

2. Mobile schedule.
Desktop grid готова; полноценный mobile agenda требует отдельного UX слоя.

3. Subject plan editor.
Backend `/admin/subject-plans` существует, но отдельного специализированного UI редактора для него нет. Raw DB/site-content editor может быть использован как fallback, но это не polished editor.

4. Trainer card editor.
Функционально доступен через raw DB editor с `trainer_feed_cards`, но специализированного редактора карточек пока нет.

5. Material metadata editor.
Функционально доступен через raw DB editor `materials`, специализированной формы пока нет.

6. Version history.
Сейчас существует audit log + rollback для update/delete. Полноценная визуальная история версий по каждой сущности пока не сделана.

7. Bulk validator.
Endpoint и UI уже есть, но его можно расширить проверками контент → source → physical media.
