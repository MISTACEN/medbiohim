## Блок 1. Химия: загруженные тесты = полноценные тесты (высокий приоритет)

Сценарий: студент узнал новый тест (как выглядит, его базу вопросов) — загружает
его в Workshop как `test_questions` (фото/текст) — и он должен стать
**полноценным тестом**, неотличимым по возможностям от созданных админом.

Сейчас тесты из Workshop живут только как материалы-вопросы. Нужно:

1. **Конвертация Workshop → банк вопросов.** У админа/модератора кнопка
   «Сделать тестом» на элементе Workshop с kind=`test_questions`:
   - OCR-текст / распарсенный PDF уже есть в item.metadata — из него
     формируются черновики вопросов (текст, варианты, правильный ответ);
   - предпросмотр-таблица с редактированием перед публикацией (как в
     admin/questions — ручная сверка обязательна, правило Pass 26A);
   - привязка к предмету/модулю/теме на этапе конвертации;
   - публикация в `questions` с `source='workshop'` и ссылкой на исходный
     workshop_item (provenance, как у chemistry_master_item_provenance).
2. **Хим-модуль как «часть теста»**: интерфейс PracticeRunner уже показывает
   задачи с фото — добавить поддержку вопросов типа «какой тут структурный
   изомер» с изображением-вариантом (options как картинки): поле
   `question.options[].image_key` + рендер в ChemRichText/PracticeRunner.
3. **Статусы конвертации** в модерской очереди: «черновик вопросов готов» →
   «проверено модератором» → «опубликовано»; отклонение возвращает элемент
   в Workshop с пояснением.

Оценка: 2–3 дня. Зависимости: нет (банк вопросов и модерация уже есть).

## Инцидент 2026-10-31: хранилище файлов недоступно (suspended bucket)

**Симптомы в консоли браузера:** `api/v1/files/upload → 502 STORAGE_ERROR`
и 404 на ресурсах хранилища.

**Корень:** Upstash Blob bucket `medbiohim-files` (432 МБ, аккаунт
ryazansevegor@hotmail.com без платёжного метода) — **suspended**. Токен
бакета отклоняется («The bucket token was rejected»), все загрузки
`/api/v1/files/upload` и `/api/v1/storage/upload` падают 502, ссылки на
объекты отдают 404. Таблица `files` при этом пуста (1 тех-строка) —
реальных файлов никогда не уезжало, потери данных нет.

**Что сделано на нашей стороне:**
- секрет `UPSTASH_BLOB_TOKEN` выставлен на воркер `medbiohim-api` через
  Cloudflare API (перевыпуск деплоя); хелперы файлов его уже читают;
- честные ошибки 503/502 в UI сохранены (никаких «тихих» подстановок).

**Требуется от владельца аккаунта (я не могу через API):**
1. Открыть Upstash Console → Blob → `medbiohim-files` → Resume
   (потребует платёжный метод) либо создать новый bucket.
2. Если создан новый bucket — передать новый токен (секрет на воркере
   обновлю той же командой), либо после Resume старый токен снова валиден.

**Альтернатива-стратегия (если Blob не оживёт):** перенести файловое
хранилище воркера на Backblaze B2 (10 ГБ бесплатно; поле
`files.storage_provider` уже допускает 'b2') — отдельная задача на ~1 день.

## Блок 5. Расписание ↔ год поступления (дизайн, следующий шаг)

Сценарий: «МБХ 201» в 2026-27 — это когорта поступления 2025 (2 курс).
Через год та же когорта станет «МБХ 301» и ей нужно уже другое расписание.
Хаос побеждается привязкой к **стабильной когорте**, а не к меняющемуся имени.

Модель (на уже существующих таблицах):
- `groups.id` стабилен; `enrollment_year` на группе (уже есть в
  groupIdentity.ts); курс = учебный год − год поступления (сентябрь — граница).
- `schedules.group_id` + `academic_year_id` уже позволяют хранить по одной
  версии расписания на группу на учебный год — история сохраняется сама.
- Загрузка файла «МБХ 201» за 2026-27: резолвер находит группу по
  (специальность, курс из имени, поток) в текущем учебном году → привязывает
  к стабильному id. В 2027-28 файл «МБХ 301» привяжется к той же группе,
  потому что вычисленный курс когорты уже 3.
- Итог для студента: зашёл на сайт — видишь расписание своей когорты
  автоматически, без поиска материалов по курсам.
- Ручной семестр (уже есть у старосты) перекрывает автоматику точечно.

Остаток реализации: резолвер привязки файлов к когортам (имя → курс/поток →
enrollment_year) в schedule-загрузке + UI подтверждения у старосты. ~1-2 дня.

## Блок 6. Workshop: видимость и роли (уточнение владельца)

- По умолчанию Workshop **публичный** (виден всем авторизованным), при
  проблемах админ переключает в manual (очередь модерации) — уже сделано
  (workshop_settings.moderation_mode).
- **Показываются только одобренные** (status=published) — уже фильтруется;
  draft/pending/hidden видны только автору и модерации.
- Удаление: автор удаляет своё (soft delete), модератор может скрыть
  навсегда — готово.
- Внутригroup материалы: workshop_items.group_id + group visibility —
  готово; «защитный слой журнала» остаётся внутри группы.
