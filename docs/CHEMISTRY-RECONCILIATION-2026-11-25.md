## Пересечение

Сравнение по нормализованному тексту вопроса (`lower(btrim(text))`, md5) между
черновиком и опубликованным набором:

- строк черновика: **944** (из них уникальных вопросов 577 — тексты повторяются
  внутри тем),
- совпадают с опубликованными: **921** строка ≈ **97,6 %**,
- уникальных для черновика: **23** вопроса.

По темам совпадение почти полное: 3.2 — 74 из 74, 3.5 — 101 из 101, 3.8 — 65 из
65; меньше всего в 1.1 (9 из 13) и 1.2 (40 из 44), но и там разница — вопросы,
зависящие от картинки («[структуры на стр. 11]»).

## Почему публиковать черновик нельзя

1. **Почти всё уже опубликовано** — 97,6 % строк дублируют набор «Оргхимия».
   Публикация добавит в каталог второй комплект тех же вопросов: у студента
   появятся две почти одинаковые темы с разными объёмами, а статистика
   разъедется.
2. **23 «уникальных» вопроса — в основном без картинок.** Примеры:
   «Все заместители проявляют электронодонорные свойства… ([структуры на
   стр. 11])», «Проекционная формула Ньюмена… Варианты 1–5 — рисунки [стр. 17]».
   Без изображений они нерешаемы, а один вопрос вообще содержит заметку
   парсера в ключе: «в скане ключа нечётко; по аналогии с заданиями 17–20…».
3. **Задания на соответствие не извлекаются.** В разборе сборника числилось
   207 таких заданий, но в `part1-questions.json` объектов `kind: "match"`
   всего **15**, и ни у одного нет ключа (`answer`), а у 14 из 15 правая
   колонка слита с текстом следующих заданий («… 62-63. Установите
   соответствие…»). Импортировать их «целиком», как требует §5.2, пока нечего:
   это не задания, а обрывки разметки.
4. **В БД нет типа `match`.** Enum `question_type` содержит только `mcq`,
   `open`, `problem`, `theory`, `practical`. Приложение при этом тип
   `matching` поддерживает (реестр типов, грейдер `matching`, карточка вопроса
   в подготовке, `MATCH_TYPES` в worker) — мешает только значение enum.
   Значит, когда появятся чистые задания, нужна одна миграция
   `alter type question_type add value 'match'`, а не переделка стека.

## Решение

- **Опубликованный набор «Оргхимия» оставить каноном** (997 вопросов, 18 тем).
- **Черновик «Химия · часть 1» не публиковать.** После подтверждения — пометить
  архивом/удалить 18 черновых тестов и их 577 вопросов (удаление — только с
  отдельного разрешения, с предварительным счётом строк до/после).
- **Задания на соответствие — отдельная задача парсера:** научить разбор
  вытаскивать левую колонку, правую колонку и ключ пар, затем добавить
  `match` в enum и импортировать только чистые задания (ожидаемо — не 207,
  а меньше; точное число даст переразбор PDF).
- **29 mcq без ключа** — не импортировать: без эталона вопрос нельзя проверить,
  он будет портить статистику.

## Что проверено

- `test_questions` / `questions` по обоим наборам — запросы к Supabase,
  только чтение.
- Пересечение — SQL по md5 нормализованного текста + разбор

- Enum `question_type` — `information_schema` + `pg_enum`.
- Поддержка `matching` в коде — `src/lib/question-types/*`,

  `integrations/cloudflare-api/src/question-format.js`.

качество 800 опубликованных mcq.
