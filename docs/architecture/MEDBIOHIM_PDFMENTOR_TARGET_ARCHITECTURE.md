# MEDBIOHIM × PdfMentor — целевая архитектура

**Статус:** действующий канон интеграции. Дата: 2026-11-20.
**Связанные документы:** [API-контракт](MEDBIOHIM_PDFMENTOR_API_CONTRACT.md) ·
[План миграции](MEDBIOHIM_PDFMENTOR_MIGRATION_PLAN.md) ·
`MEDBIOHIM_PDFMENTOR_PLAN.md` (исходный план, снимок).

Документ описывает границы двух продуктов. Всё, что противоречит ему, считается
ошибкой проектирования, а не «второй реализацией».

---

## 1. Два продукта, одна учебная среда

| MEDBIOHIM | PdfMentor |
|---|---|
| Пользователи, группы, роли | Просмотр и чтение документов |
| Предметы, темы, учебный план | Извлечение текста, блоков, координат |
| Тесты, билеты, коллоквиумы | OCR сканов |
| Проверка схем и письменных ответов | Разметка BASE / MAIN / ADVANCED |
| Прогресс, ошибки, слабые темы | ИИ-тьютор по документу, маршрут |
| Каталог микропрепаратов, диагностикум | Доска знаний, заметки, закладки |
| Владение оригинальными файлами и правами | Производные данные: страницы, блоки, индексы |
| Решения о доступе (RLS, публикации) | Поиск по содержимому и между документами |

Ключевое правило: **MEDBIOHIM знает, что и зачем изучать; PdfMentor знает, что
написано в документе и где именно.**

## 2. Границы

- Общих таблиц нет. Интеграция — только HTTP + версионируемые идентификаторы.
- MEDBIOHIM не хранит страницы, блоки и разметку PdfMentor.
- PdfMentor не хранит предметы, группы, права и оценки MEDBIOHIM.
- Каждый сервис работает самостоятельно, если второй недоступен: чтение в
  PdfMentor не зависит от доступности MEDBIOHIM, а учебная платформа — от ИИ.

## 3. Идентичность

```
MEDBIOHIM (Supabase Auth)  ──код──▶  PdfMentor (sessions)  ──▶  cookie pm_session
        IdP                          локальный профиль            на домене PdfMentor
```

1. Регистрация в MEDBIOHIM — основной путь. Отдельный пароль в PdfMentor не нужен.
2. У пользователя уже есть аккаунт PdfMentor — явная привязка (`intent=link`),
   подтверждённая двумя активными сессиями. Автоматическая склейка — только при
   подтверждённом email.
3. Пользователь пришёл только в PdfMentor — работает собственная регистрация.

Транспорт кода — **form_post**: браузер отправляет одноразовый код в PdfMentor
POST-формой. Код не попадает в query, Referer и историю. Обмен выполняет сервер
PdfMentor, подписывая запрос HMAC (`BRIDGE_SECRET`). Код живёт 60 секунд и
расходуется атомарно (`getdel` в Redis).

## 4. Документы

```
MEDBIOHIM: files (оригинал, владелец, права)
      │  идентификатор + версия + checksum
      ▼
PdfMentor: external_source → источник → версии → страницы → блоки → фрагменты
```

- Оригинал остаётся в MEDBIOHIM. PdfMentor получает доступ, а не копию.
- Производные данные (страницы, координаты, OCR, индексы) — в PdfMentor и
  пересоздаваемы.
- Пользовательские заметки и выделения принадлежат пользователю PdfMentor.
- Новая версия оригинала не уничтожает заметки: она создаёт новую версию
  обработки, а объекты с `origin=user` сохраняются.

## 5. Права

| Действие | Кто решает |
|---|---|
| Открыть, скачать оригинал | MEDBIOHIM |
| Обработать документ | MEDBIOHIM разрешает, PdfMentor выполняет |
| Вести заметки и выделения | PdfMentor |
| Опубликовать для группы | MEDBIOHIM |
| Отозвать доступ | MEDBIOHIM (немедленно, при следующем запросе) |

Скрытие кнопки во фронтенде не является проверкой доступа: каждое чтение
документа проходит серверную проверку.

## 6. Встраивание

- `/mentor/*` в MEDBIOHIM — точка входа: одноразовый код + учебный контекст.
- Без iframe: сторонние cookie, мобильный UX и история навигации ломаются.
- Целевой вариант — прокси на том же origin или поддомен с cookie на apex;
  решение фиксируется при выборе домена (см. §9).
- Старый просмотрщик MEDBIOHIM выводится только после parity-чеклиста.

## 7. Юрисдикция и приватность

PdfMentor документирует хранение и обработку данных в РФ (152-ФЗ), MEDBIOHIM
работает на Vercel / Cloudflare / Supabase. Поэтому:

- передача содержимого документов в production **запрещена до отдельного
  решения владельца** (локальный контур, согласие пользователя или смена
  размещения);
- в dev допускается мост между двумя локальными инстансами;
- ключи и секреты живут только в Cloudflare secrets и `.env.local`, никогда —
  в репозитории, логах и браузере.

## 8. Микропрепараты: данные, а не текст

Диагностикум и методические карточки строятся на существующем каталоге:

- `trainer_feed_cards` — карточка препарата (`preparation` JSONB: name, organ,
  stain, captions, imagePath), `tags`, `mode_set`, тема плана;
- `trainer_atlas_cards` — изображение и координатные `annotations`;
- `trainer_atlas_answers` — история ответов «найди структуру».

Новые таблицы добавляют только то, чего нет: методический гид (шаги поиска,
диагностические признаки, включения, дифференциал, частые ошибки, источники) и
попытки диагностикума. Отдельный «второй каталог препаратов» запрещён: он
разъедется с атласом.

## 9. Открытые решения владельца

1. Размещение PdfMentor для production (определяет, будет ли Document Bridge
   вне dev).
2. Домен встроенного режима: `mentor.<домен>` или прокси `/mentor` на том же
   origin.
3. Порядок коммитов в `main` обоих репозиториев (интегратор / maintainer).
