## 3. Найденные проблемы по важности

1. **Покрытие 7,6 %.** Методички есть у 18 карточек, остальные 218 в диагностикум
   не попадают: разделы строятся из `preparation_guides`. Без методичек
   диагностика работает как «угадай название по картинке».
2. **ЭМ смешаны с препаратами** в вопросах диагностикума. Документ требует
   отдельный банк; сейчас разделение только визуальное в атласе.
3. **Нет экзаменационного режима.** Ни таймера, ни запрета эталона, ни отдельной
   попытки — требование §7.4 не выполнено.
4. **Нет наборов диагностики.** Нельзя запустить «первую диагностику» как набор:
   только разделы методичек. Вторая диагностика архитектурно не поддержана.
5. **Расхождение 18/19.** В документе 19 названий, в базе 18 методичек; пропали
   «Осевые органы» (карточка в банке есть). Это не «две позиции объединили»,
   а потерянная позиция — её нельзя закрывать молча.
6. **Карточка пустая.** 0 описаний и 0 подписей на 236 карточек: режим изучения
   показывает изображение и (для 18) методичку, но не «морфологические признаки»
   как поля карточки.
7. **Дубли вместо нескольких изображений.** 236 карточек на 119 названий:
   «кровь мазок» — 10 карточек, «трубчатая кость» — 8. В задании «определи
   препарат» это даёт несколько верных вариантов с одним названием.
8. **SRS не связан с препаратами** (0 из 236): требование «изученный препарат
   отправляется на повторение» не выполнено.
9. **Статистика без «правильно»**: 31 попытка, 0 верных. Баллы 0/33/67
   встречаются, 100 — ни разу. Нужна проверка, не слишком ли строг порог
   «верно» (возможно, требуется 100 % по всем частям).
10. **Нет UI для добавления карточки** с описанием, структурами и подписями —
    только импорт, поэтому наполнение банка не масштабируется.

## 9. Проверка под логином 2026-11-26 (продолжение)

Проверка на production с реальной сессией вскрыла три дефекта, которые не
видели ни типы, ни тесты по исходникам:

1. **Ограничение БД не знало новых режимов.** `diagnosticum_attempts_mode_check`
   разрешал только identify/structures/differential/complex/schema: вставка
   `exam`/`electronogram` падала с SQLSTATE 23514, API отвечал 503. Добавлена
   аддитивная миграция `20261126_diagnosticum_modes.sql`, применена к боевой
   базе после явного разрешения; 23514 теперь даёт понятное «нужна миграция»,
   а не «БД недоступна».
2. **Переключатель режимов не работал.** `mode = controlledMode ?? localMode`:
   клик по «Экзамену» менял только локальный state, а задание стартовало в
   `complex`. Внешний режим теперь только стартовое значение.
3. **В ЭМ оставались подсказка и «Методика поиска».** Подсказок у ЭМ нет
   (сервер отвечает 409), а кнопка методички открывала пустую панель: обе
   убраны из интерфейса.

Фактическая проверка после исправлений (сессия пользователя, production):

- `complex`: start 200, 3 части, подсказка 200, ответ с разбором и `guide_key`;
- `exam`: start 200, 4 варианта, подсказка 409 `CONFLICT`, ответ содержит
  только `correct/score/hints_used/exam` — без `parts` и `guide_key`; полная
  серия 10 вопросов пройдена в UI: эталоны не показывались, итог
  «без ошибок 7 из 10 · средний 70 · лучший 100», кнопка нового экзамена есть;
- `electronogram`: start 200, раздел «Электронограммы», 4 варианта, подсказка
  409, ответ с одной частью и пустым `guide_key`, разбор без кнопки методички;
- в UI видны ровно три режима: «Разбор препарата / Экзамен / Электронограмма».

Побочный эффект проверки: в аккаунте остались тестовые попытки (несколько
complex/exam/EM) — это реальные строки `diagnosticum_attempts`, при желании

## 19. Карточка препарата v2 и 19-я методичка 2026-11-26 (шаги 3–4, 8)

Закрыта главная причина, по которой банк не растёт: у карточки не было ни
нескольких изображений, ни подписей к структурам, ни архива, а редактор умел
только массовый импорт. Плюс закрыт открытый вопрос §5.1: «Осевые органы»
больше не missing.

### Схема (миграция `20261126_trainer_card_v2.sql`, применена)

Миграция аддитивная, применена к боевой базе после явного разрешения
пользователя (`scripts/apply-migration.mjs … --yes`):

- `trainer_feed_cards.is_archived` + `archived_at` — архив вместо удаления,
  история попыток и связей сохраняется; частичный индекс по `is_archived`;
- таблица `trainer_card_images` (id, card_id, `object_key` **или**
  `external_url`, caption, hotspots, sort_order): ровно один источник
  (`num_nonnulls(...) = 1`), ссылка только `https://`, hotspots — jsonb-массив;
- RLS: читают `anon`/`authenticated` только для опубликованной и неархивной
  карточки, запись — только `service_role`;
- `trainer_feed_cards_public` пересоздано с `and c.is_archived = false`
  (тело прежнее, вырезание ключей ответов сохранено).

### API

- `GET /trainers/feed` и `GET /trainers/feed/:id` отдают `hotspots` основной
  картинки и `images[]` (id, caption, sort_order, hotspots), архивные карточки
  не отдаются вообще;
- `GET /trainers/feed/:id/images/:imageId` — байты дополнительного снимка:
  проверяет, что карточка опубликована, не в архиве и снимок принадлежит ей;
  `external_url` и публичный Blob проксируются с тем же `cache-control`;
- админ: `GET /admin/trainer-cards` (поиск), `GET /admin/trainer-cards/:id`,
  `PATCH` (архив, подписи, текстовые поля препарата, hotspots),
  `POST/PATCH/DELETE /admin/trainer-cards/:id/images[/:imageId]`.
  Чтение — админ и модератор, запись — только админ и только service-role;
  ключи хранилища и ссылки валидируются (`safeObjectKey`, `https://`), не
  больше 8 снимков и 60 указателей на изображение.

### Интерфейс

- `/admin/trainer-cards` — редактор карточки: поиск препарата, архив/возврат,
  название/орган/окраска, подписи, указатели кликом по изображению (координаты
  в долях 0–1), дополнительные снимки по ключу хранилища или https-ссылке,
  удаление снимка. Методичка правится в соседнем разделе — редактор карточки
  её не трогает.
- Атлас: в просмотрщике появилась галерея дополнительных снимков и указатели,
  нарисованные поверх изображения внутри сцены с зумом (масштабируются вместе
  с картинкой), плюс нумерованный список подписей.

словарь структур `neural-tube`, `notochord`, `somites`.

Источники содержимого и границы (записаны в `preparation_guides.sources`):

- лекция `lec-hist-embryology` — комплекс осевых органов (хорда, нервная
