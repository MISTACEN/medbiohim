# MEDBIOHIM — концепция и полное описание проекта

## 1. Идея проекта

MEDBIOHIM — единая бесплатная образовательная платформа для студентов медицинской биохимии и смежных дисциплин. Это не просто набор тестов или электронный дневник: проект объединяет учебный план, расписание, материалы, практику, тестирование, подготовку к экзаменам, задания, прогресс, учебное сообщество и административное управление в одном учебном пространстве.

Главная идея: студент должен видеть не разрозненные сервисы, а понятный учебный маршрут:

**учебный план → занятие → предмет/тема → материалы → вопросы и тесты → задание → результат → пробелы → повторение.**

Платформа должна помогать не только «пройти тест», но и понимать, что именно нужно изучить сейчас, что уже освоено, где есть ошибки и что повторить.

## 2. Принципы проекта

- Функциональность прежде всего: бесплатная инфраструктура не должна приводить к искусственному урезанию возможностей.
- $0 обязательных расходов.
- Supabase/PostgreSQL — каноническая база данных.
- Дополнительные бесплатные сервисы только дополняют платформу.
- Права, ответы, оценки, группы и контекст проверяются на сервере.
- Начатая подготовка/попытка сохраняет собственный снимок вопросов и ответов.
- Банк вопросов, тесты, материалы и учебный контекст одного предмета не смешиваются с другим.
- Сначала deterministic, затем AI.
- Рабочая версия фиксируется как baseline перед крупными изменениями.
- UI должен помогать учиться, а не скрывать учебный контент.
- Сначала оптимизация: cache, pagination, lazy loading, streaming, batching, deduplication, разделение metadata/binary.

## 3. Что входит в платформу

### Студент
Авторизация и профиль; группа, курс, семестр и академический контекст; учебный план; расписание; задания и домашняя работа; материалы; тренажёры и атлас; банк вопросов с ответами без запуска теста; тесты; подготовка к тестам/билетам; история попыток; прогресс и учебные пробелы; жалобы на вопросы; сообщество; настройки.

### Администратор
Пользователи и роли; группы и академический контекст; предметы, модули, темы и учебный план; вопросы и тесты; задания; материалы; жалобы; тренажёры; база данных; импорт/экспорт; аудит; безопасный откат; будущий единый Operations Center для БД и файлов.

## 4. Учебная логика

Основная модель — не «страница тестов», а учебный граф:

**Предмет → модуль → тема → занятие → материалы → вопросы → тест → результат.**

Учебный план связывается с вопросами и тестами. При открытии темы студент должен понимать дату занятия, число вопросов, связанные тесты, материалы, выполненное и то, что требует повторения.

## 5. Расписание + задания

Целевой flow:

**Расписание → дата → предмет → занятие → задание → выполнение/сдача → единый статус.**

Задание связано с группой, предметом, занятием/датой и учебной сессией. Цель — единый mobile/desktop-сценарий без разрыва между «Расписание» и «Задания».

## 6. Тесты и банк вопросов

Банк вопросов — самостоятельная учебная библиотека, тест — режим проверки знаний.

Студент может открыть предмет, открыть банк, увидеть вопрос и правильный ответ, найти тему, пожаловаться на ошибку и отдельно запустить тест или подготовку.

Поддерживаются single-choice, multiple-choice, свободный текст, последовательный режим, полный банк, номера вопросов, история попыток, server-authoritative scoring и immutable snapshots.

## 7. Умная проверка свободного ответа

Проверка каскадная:

1. Нормализация.
2. Точное совпадение без учёта орфографических мелочей.
3. MCQ проверяется deterministic без AI.
4. Для свободного ответа при необходимости вызывается AI.
5. AI получает вопрос и эталонный ответ и сравнивает смысл.
6. Орфографические ошибки не делают правильный ответ неправильным.
7. Допускаются синонимы, нормальные сокращения, другой порядок слов и грамматические формы.
8. Существенные ошибки, пропуски ключевой части и противоречия отклоняются.
9. Неуверенный AI не должен автоматически превращать ответ в ошибку.

AI необязателен: базовые тесты должны работать без него.

## 8. Гистология

Гистология — отдельный предметный контентный слой. Физические изображения и документы не должны храниться целиком в Supabase только ради удобства.

Модель:

**Supabase metadata/source_key/path → SpaceWeb physical media → PHP API → frontend.**

Канонический runtime-root: /public_html/content/histology/

Зафиксированы сотни физических файлов, 206 trainer cards, включая 28 electronograms, captions и материалы.

Строка в БД не считается доказательством существования файла. Финальная проверка: физический файл, правильный путь, HTTP 200, корректный MIME и отображение во frontend.

## 9. Органическая и физическая химия

Единый master catalog содержит 436 элементов: 260 открытых заданий и 176 тестовых вопросов. Сохраняется provenance независимых источников, текстовые формулы и статус проверки.

Image-only structural formulas не восстанавливаются догадкой, а неподтверждённый OCR не заменяет production answers.

## 10. Материалы и контент

Материалы организуются по предмету и учебным темам. Различаются metadata Supabase, физический файл, учебный материал, вложение лекции, изображение тренажёра, документ, PDF, фото препарата и electronogram.

Отсутствие физического файла не маскируется наличием metadata.

## 11. Административный Operations Center

Будущая цель — PC-style центр управления.

Database Console: дерево таблиц, поиск, строки, фильтры, сортировка, пагинация, JSON, редактор, связи, история, bulk edit, dry-run импорта, XLSX/CSV, audit и rollback.

File & Storage Center: SpaceWeb, Backblaze B2 и Supabase metadata; путь/object key, MIME, размер, checksum, существование, orphan-файлы, metadata без файла, дубликаты, безопасные move/rename/archive/delete.

Operations Dashboard: состояние Supabase/SpaceWeb/B2/Vercel, ошибки интеграций, квоты, операции, аудит и backup/export snapshots.

Обычный администратор не получает произвольный SQL: опасные операции проходят whitelist, серверную проверку роли, validation и audit.

## 12. Архитектура инфраструктуры

- GitHub — код, миграции, документация и небольшие декларативные артефакты.
- Vercel Hobby — frontend.
- SpaceWeb Free — PHP API/runtime и тяжёлые physical media.
- Supabase Free — PostgreSQL/Auth/RLS/canonical metadata.
- Backblaze B2 Free — дополнительные объекты/backup при необходимости.
- Другие бесплатные сервисы — только специализированные дополнения: cache/CDN, push, OCR, search, monitoring, analytics, backup.

Никакая дополнительная система не становится второй канонической БД.

## 13. Бесплатность

Правило проекта:

**не «free tier → убрать функцию», а «функция → найти бесплатный способ реализовать её эффективно».**

Порядок: измерить нагрузку → найти узкое место → кэширование → pagination/lazy loading → сократить повторные запросы → deduplication → отделить metadata от binary → распределить тяжёлые данные → добавить бесплатный сервис при реальной пользе → проверить отсутствие обязательной оплаты.

## 14. Дизайн и устройства

Единый визуальный язык — современный чистый интерфейс с beta-темой Frutiger Aero × Win7 Glass × iOS.

Приоритеты: iPhone/iOS, Android, Windows, macOS, Safari, Chrome, Edge, Firefox и Яндекс Браузер. Особое внимание мобильному админ-разделу, тестам, подготовкам, тренажёрам, материалам, расписанию, тёмной теме и скорости.

## 15. Безопасность и данные

Клиент не является источником правильного ответа; оценки считаются сервером; группа и предмет проверяются сервером; попытки привязываются к академическому контексту; результаты воспроизводимы через snapshot; admin mutations защищены ролью; RLS — дополнительный уровень; cross-subject/cross-group leakage недопустим; ошибки БД не должны молча превращаться в пустой успешный ответ; optional external services не должны ломать основной сайт.

## 16. Будущее развитие

AI-репетитор, персональные планы повторения, автоматическое определение пробелов, интеллектуальный подбор вопросов, OCR и импорт учебных материалов, поиск по учебному контенту, push-уведомления, аналитика, автоматическая сверка файлов, backup/export и дополнительные бесплатные сервисы.

Все новые функции добавляются поверх существующей архитектуры и не ломают текущие рабочие потоки.

## 17. Release gate

Готовность проверяется не только сборкой. Release gate включает production frontend/API, Auth и /me, группы и академический контекст, расписание, задания, материалы, тренажёры, тесты, подготовки, банк вопросов, ответы, жалобы, admin, мобильные сценарии, физические Histology media, chemistry content, server-authoritative scoring, отсутствие cross-subject/cross-group leakage, CI/build, runtime smoke, документацию и rollback baseline.
