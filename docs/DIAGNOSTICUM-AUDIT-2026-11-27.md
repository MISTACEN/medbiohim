## 2. Найденные дефекты

### P0. Утечка ключа ответа в сериях (экзамен фактически не контролируется)

* `workers/api/src/routes/diagnosticum/sessions.ts:203-211` (старт серии) и `:258-270` (GET серии)
  отдают `guide_key` в каждом элементе **до** ответа.
* `workers/api/src/routes/diagnosticum/model-questions.ts:52-56`: правильный вариант «Что это за препарат?»
  имеет `id = guide.key`.
* Следствие: `option.id === item.guide_key` даёт верный ответ без изображения.

Практическое подтверждение: три экзаменационные серии по 10 вопросов пройдены на 10/10, 0/10 и 5/10
**без опоры на картинку** (часть картинок вообще не загружалась, см. P1). Это не «взлом», а данные,
которые API сам кладёт в браузер.

Лечение: в статусе `in_progress` не отдавать `guide_key`; использовать непрозрачные id вариантов
(`opt_<hash>` от attempt_id + индекса), `guide_key` возвращать только в `reviewOf` после `finish`.

### P0. Порядковые id утверждений кодируют правильность

`model-questions.ts:97-100` и `:128`, `:216`: верные утверждения получают `id = f0..f2`,
обманки — `x0..x1`. Достаточно отметить все `f*`, не читая текст. Та же природа, что P0-1,
но доступна и в одиночном `/start` (без серии).

### P1. Бонус-снимки не отдаются: `imageStatic` редиректит на домен Worker

`workers/api/src/routes/trainers/03-image.ts:100-103`:

```ts
return c.redirect(new URL(staticImage, new URL(c.req.url).origin).toString(), 302);
```

`c.req.url` — это `https://medbiohim-api.ryazansevegor.workers.dev/...`, а `/library/...` лежит на сайте
(Vercel). Живой лог: `404 GET https://medbiohim-api.ryazansevegor.workers.dev/library/lectures/gistologiya/preparaty-bonus/ct-hyaline-cartilage/shot-01.jpg`,
в UI — «Изображение недоступно». В экзамене такие вопросы невозможно решить честно (и они же
маскировались утечкой P0-1).

Лечение: редирект на origin сайта (`PUBLIC_SITE_ORIGIN`/`VERCEL_URL`) или проксирование байтов,
как уже сделано для Drive/Blob.

### P1. «Повторить ошибки» → «Экзамен по выбранным» = 422

* `/diagnosticum/mistakes` (`session.ts:308-352`) отдаёт `card_id` по **всем** режимам, включая
  электронограммы (`feed-em-*`) и карточки без методички.
* `DiagnosticumStats.tsx:64-65` склеивает их в `?cards=` и ведёт на старый тренажёр.
* `buildCardSeries` (`sessions-model.ts:121-159`) считает такие карточки `missing`, а
  `sessions.ts:108-116` отвечает `CARD_SELECTION_UNAVAILABLE` → в UI «Часть выбранных карточек
  недоступна для разбора».

Лечение: фильтровать очередь по `mode_set != electronogram` и наличию гида; либо в UI отбрасывать
неподходящие id и показывать «12 из 20 пойдут в серию».

### P1. Таймер не восстанавливается из серии

`timer_sec` пишется при старте (`sessions.ts:135`), но клиент его нигде не читает
(`grep timer_sec src` → только отправка). При восстановлении берётся локальный default 90
(`DiagnosticumRunner.tsx:210,236`). Сессия, начатая с 60 с, после reload снова идёт с 90 с.

### P1. Гонка «восстановление серии» vs «Начать экзамен»

`DiagnosticumRunner.tsx:152-239`: эффект восстановления не отменяется и не проверяет, что попытка
уже заменена. Если `GET /sessions/:id` ответит после `start()`, восстановленный вопрос перетрёт
только что созданный, а `submit` уйдёт в старую серию. В живом прогоне restore сработал корректно,
но гонка достижима на медленной сети (лечение: `AbortController` + проверка `resumeTried`/номера серии).

### P1. Нет списка сессий — завершённый экзамен не открыть

`GET /diagnosticum/sessions` существует только как `POST` + `GET /:id`. В «Истории тренировок»
(`listTrainings`, старый движок) серий нет: 3 экзамена по 10 вопросов не появились, счётчик остался 24.
Разбор доступен только сразу после финиша и после reload той же вкладки, пока жива `sessionStorage`.

### P2 (мелкое, но заметное)

1. `DiagnosticumAnswerActions.tsx:54` — `Подсказка {hintsUsed + 1}/{hintsTotal}` → «Подсказка 5/4».
2. `sessions.ts:210,268` — `hints_total: 4` вместо `MAX_HINTS`.
3. Мёртвые режимы `identify / structures / differential / schema`: UI их не показывает
   (`DiagnosticumModeChips.tsx:13`), но они есть в API и в статистике («Найди структуры: 1/2» и т. п.).
4. Селектор «10 вопросов» не влияет на серию по выбранным карточкам: длина = число `card_ids`.
5. `/trainers/diagnosticum` → `?section=diagnosticum`, но `HistologyTrainer.tsx:78-80` читает только
   `section=atlas`; параметр мёртвый.
6. `/diagnosticum/mistakes` возвращает `total = items.length` после дедупликации и лимита 20.

## 3. Как объединить режимы (без потери функционала)

Сейчас в одной вкладке живут **два движка**:

* новый — `/api/v1/diagnosticum/*` (`complex`, `exam`, `electronogram`, скрытые `identify/structures/
  differential/schema`), серверный ключ, подсказки, серии, статистика, очередь ошибок;
* старый — `/api/v1/trainings*` (`createHistologyTraining` / `answerTrainingQuestion` / `completeTraining`),
  своя история, свободный ввод, `label_mode`, layout.

Плюс третий вход — «Повторить ошибки», который уводит в старый тренажёр.
Целевая модель: **один движок (diagnosticum), один экран, одна история, оси вместо режимов.**

### Этап 0 — безопасность и честность (без изменения UX)

* закрыть P0-1/P0-2: непрозрачные id вариантов, `guide_key` только в разборе;
* поправить `imageStatic` (P1);
* фильтр очереди ошибок (P1);
* `hints_total = MAX_HINTS`, подпись подсказки.

Проверка: 10/10 «вслепую» больше невозможно; повтор ошибок стартует серию, а не 422.

### Этап 1 — оси вместо режимов

`POST /diagnosticum/start` и `POST /diagnosticum/sessions` принимают
`parts: ("preparation" | "structures" | "statements" | "differential")[]`.
`mode` остаётся вычисляемым (для старых строк и ссылок):

| Было | Стало |
| --- | --- |
| `identify` | `parts=["preparation"]` |
| `structures` | `parts=["structures"]` |
| `differential` | `parts=["differential"]` |
| `schema` | `parts=["statements","preparation"]` |
| `complex` | все доступные оси |

UI: в «Разборе» — чипы осей (как сейчас чипы режимов), «Экзамен» = `preparation` + таймер + без подсказок.
Ни один сценарий не теряется: это ровно те же сборки `buildModeQuestion`, только выбор оси явный.

### Этап 2 — «Своя серия» на одном движке

`buildCardSeries` уже готов (`mode + card_ids`). Остаётся:

* перевести вкладку «Своя серия» на `POST /sessions {card_ids, mode:"complex"}`;
* перенести настройки: количество (для серии по разделу), темы→`section`, «режим ответа»;
* свободный ввод — единственная реальная потеря. Либо добавить `answer_mode: "input"` в проверку
  (нормализация названия, допуски), либо оставить старый тренажёр отдельным «Свободным режимом»
  и назвать это явно, а не прятать за тем же табом.

### Этап 3 — одна история и статистика

* `GET /diagnosticum/sessions?limit=` — список серий (сейчас его нет);
* блок «История» читает серии + старые `trainings` (read-only, с пометкой источника);
* статистика уже считается по `diagnosticum_attempts`; добавить `source` и свернуть legacy-режимы
  в группу «Ранние режимы», чтобы «Найди структуры: 1/2» не выглядел живой кнопкой.

### Этап 4 — чистка

удалить `DiagnosticumModeChips`/`?section=diagnosticum`/дубль `hints_total`; `document`
обновить в `API-CONTRACTS.md`.

## 4. Чек-лист «объединение не деградировало»

Прогнать после каждого этапа (ровно то, что уже проверено живьём):

1. Разбор: 4 подсказки, −10 каждая, 100 и 60 баллов, «Лишнее/Не отмечено», «В повторение», «Методика поиска».
2. Экзамен: 10/20/30 × без таймера/60/90; 100 %, 0 %, 50 %; авто-сабмит по времени; reload → «Серия продолжена»; итог и разбор 1…N.
3. Электронограммы: без подсказок, без методички, отдельный банк.
4. Своя серия: количество 10/20/30/50/Все, темы, выбор карточек, ввод вручную, «Завершить» → «Результат».
5. Ошибки → «Повторить ошибки» → серия стартует (а не 422), «В повторение» идемпотентно.
6. Статистика: `ответов/верно/средний/подсказки`, по разделам и режимам, слабые разделы.
7. История: серия экзамена открывается на разбор; старые тренировки не исчезли.
8. Картинки: `feed-prep-*`, бонус-снимки (`imageStatic`), электронограммы — все 200.
9. Доступ: чужая сессия/попытка → 404; гранты `answers` не выданы `authenticated`.
10. `npm run typecheck`, `npm run lint`, `npm run test:unit`.

## 6. Что не проверено

* Свободный ввод в «Своей серии» (кнопка есть, сценарий не прогонялся).
* Серии 20/30 вопросов и таймер 90 с (проверены 10 вопросов и 60 с; лимиты сервера — 1…30 и 10…3600).
* Раздел «Первая диагностика» (набор из 19) и фильтр по разделу в экзамене.
* Мобильная вёрстка и клавиатурная доступность.
* Поведение при `NOT_MIGRATED` (в текущей БД миграции применены).
