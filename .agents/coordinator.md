# Координатор MEDBIOHIM

## Мандат

Координатор — единственная точка планирования и передачи информации между независимыми верхнеуровневыми агентами. В текущем процессе эту роль выполняет внешний координатор (пользователь + ChatGPT); это не отдельный daemon и не обязательный агент внутри ZCode.

Координатор делит задачу, назначает владельцев файлов, согласует contracts, собирает артефакты, выбирает интегратора и принимает результат.

## Перед распределением

1. Получи актуальный `main` и зафиксируй SHA; прочитай `AGENTS.md`, релевантные документы и код.
2. Разбей запрос на независимые deliverables по файлам/каталогам, а не только по названиям функций.
3. Выдели shared/hotspot-файлы (`workers/api/src/index.ts`, `workers/api/src/routes/trainers.ts`, `src/lib/api.ts`, Next proxy, migrations) и назначь каждому ровно одного владельца.
4. Для межслойной задачи сначала зафиксируй contract: endpoint, schema, auth, RLS, storage key, error/status semantics.
5. Если безопасно разделить нельзя, назначь одному агенту read-only аудит, второму — реализацию после аудита; не создавай искусственную параллельность.

## Выдача независимых задач

- Каждый агент получает самодостаточный prompt: цель, base SHA, контекст, allowlist, запреты, критерии приёмки, команды проверок и формат отчёта.
- Не упоминай второму агенту существование первого; не проси агентов связываться, ждать друг друга или синхронизировать рабочие копии.
- Не передавай общий writable directory. У каждого — собственная копия/worktree и diff.
- Не разрешай обоим менять один файл. Для shared file назначь одного writer, второму оставь read-only review.

## Интеграция после завершения

1. Получи оба patch/diff и отчёта. Сверь base SHA и список файлов.
2. Выбери одного из тех же агентов на отдельную задачу интеграции. Передай ему patch как обезличенный артефакт, не открывая чужой диалог и не организуя контакт между агентами.
3. Интегратор работает в чистой integration workspace. Применяет изменения последовательно, не переписывает чужую работу молча и не пушит в `main`.
4. При конфликте остановись, сохрани оба варианта, определи владельца файла и запроси точечное решение. Не решай семантический конфликт автоматическим выбором ours/theirs.
5. QA/Security получает интегрированный diff read-only; затем выполняются релевантные проверки.
6. Только после review и разрешения maintainer интегрированный результат может попасть в `main` одним последовательным commit.

## Критерии приёмки

- Все изменения в назначенных путях.
- Контракты frontend/backend/database/storage согласованы.
- Нет секретов, пользовательских данных или необоснованных destructive операций.
- Проверки перечислены с точными результатами; непроверенное помечено.
- Patch применим к base SHA; итоговый diff не содержит посторонних файлов.
- Статусы «готово», «интегрировано», «тесты пройдены», «задеплоено» и «проверено в production» не смешиваются.

## Subagent-делегирование

Координатор может назначить родительскому агенту внутренние роли из его профиля. Делегирование допустимо только внутри изолированного workspace и при реальной поддержке host. Не предполагай, что ZCode поддерживает subagents, пока это не подтверждено.
