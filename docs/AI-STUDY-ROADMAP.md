# Дорожная карта: ИИ-подготовка к коллоквиуму/КР/экзамену (по образцу «Школы Сеченова»)

> Целевой сценарий: студент пишет «хочу подготовиться к коллоквиуму по физиологии» → платформа понимает,
> к какому дню готовиться, собирает темы из плана, лекции, тесты, вопросы и материал, считает готовность
> в процентах, составляет план по дням с «почему» у каждого шага, генерирует карточки и сжимает
> повторения под дату (финальный прогон накануне вечером).

Референс: [школасеченова.рф](https://xn--80aafla1ahtef3a7eg.xn--p1ai/) — разбор их механики по экранам.
Дата: 2026-11-14. База: main `4035b703` (после релиза учебного контура).

## 1. Сквозной сценарий (что должно работать после дорожной карты)

1. Студент открывает /study → видит карточку события: «Коллоквиум по вегетативной фармакологии — через 9 дней · Готовность 62%».
2. Нажимает «Подготовиться» → ИИ собирает план на 9 дней: темы из плана предмета, разбитые по дням
   («4 темы коллоквиума по 2 за 3 дня»), с «почему» у каждого шага; повторения сжаты под дату
   (финальный прогон накануне вечером).
3. Каждый день плана — конкретные действия: «Открыть лекцию 12», «Пройти тест темы», «Собрать пак
   карточек по теме», «Прогнать SRS-повторения» — все ведут на готовые страницы.
4. ИИ-тьютор отвечает по лекциям физиологии со сносками [1] и списком источников.
5. Ошибки в тестах — кнопка «Объяснить · ИИ» и автоматический уход в карточки повторения.
6. Интерактивный конспект лекции: пропуски по ключевым терминам, мгновенная проверка, ошибки в SRS.
7. Ночью агент готовит разборы на завтра, утром — отчёт в Telegram: «двойник сдал пробный коллоквиум на 7/10».

## 2. Карта фич «Школы Сеченова» → реализация в MEDBIOHIM

### 2.1. Ядро: «Готовность к событию» + план по дням ⭐ (высший приоритет)

**У Сеченова:** «Готовность к коллоквиуму 62%», «План на 9 дней: 4 темы по 2 за 3 дня», «Повторения сжаты под дату: финальный прогон 11-го вечером», «почему» у каждого шага.

**Что есть:** событие (schedule_entries.event_kind=colloquium), план предмета (weeks→lectures→topics),
прогресс тем (user_topic_progress.percent), чеклист-черновик без сохранения и без привязки к темам.

**Реализация:**

1. **Связь «событие → темы»** (`workers/api/src/routes/study-prep.ts`, новый):
   - вход: schedule_entry_id → event_kind+subject_id+date;
   - темы берём из плана предмета: `subject_plan:<slug>` → недели вокруг даты события → lecture_id →
     `topic_id` лекций (histology) / темы physiology из `subject_plan` payload `topic_id`;
   - если темы не найдены — fallback: темы предмета с прогрессом <70%.
2. **Готовность**: `mastery = avg(user_topic_progress.percent)` по темам события (или 0 для
   непрогрессированных тем = 0%). Отдаётся в `/academic/state` (расширить upcoming полями
   `prep_topics[]`, `mastery_pct`).
3. **План по дням**: таблица `study_plans`:
   ```sql
   create table public.study_plans (
     id uuid primary key default gen_random_uuid(),
     user_id uuid not null references public.users(id) on delete cascade,
     schedule_entry_id uuid references public.schedule_entries(id),
     subject_slug text,
     event_date date not null,
     days jsonb not null default '[]',      -- [{date, items:[{kind, title, href, why}]}]
     topics jsonb not null default '[]',    -- [{topic_id, title, mastery_pct}]
     status text not null default 'active', -- active|completed|abandoned
     generated_by text not null default 'ai', -- ai|rules
     created_at timestamptz default now(), updated_at timestamptz default now()
   );
   ```
   RLS owner-only. Генерация детерминированная (правила: темы по mastery asc, поровну на дни,
   финальный прогон = день перед событием, SRS-повторения сжимаются: `due_at` карточек тем
   принудительно ≤ event_date) + LLM-проход для формулировок и порядка (как в TodayPlan:
   правила дают каркас, ИИ — текст «почему»). Worker:
   `POST /study-prep/plan {schedule_entry_id}` → создаёт/обновляет план (идемпотентно на событие),
   `GET /study-prep/plan?event=` → текущий. **Сохраняется** (в отличие от нынешнего чеклиста).
4. **UI**: карточка события в /study (AgendaTimeline) получает кнопку «План подготовки» → секция
   «План на N дней» с днями, чекбоксами (прогресс в `study_plans.days[].done`), «почему» свёрнуто.
   Плюс «Готовность: 62%» с прогресс-баром и список тем с их mastery.

**Оценка:** 2–3 дня. Зависимости: ничего нового, всё из существующих таблиц.

### 2.2. RAG тьютора по всем предметам + сноски-источники ⭐

**У Сеченова:** тьютор отвечает со сносками [1], [2], под ответом — источники и «какой видеоразбор посмотреть»; два режима «Точный/Быстрый».

**Что есть:** `buildLectureContext` ищет только в `histology_lectures` — для «коллоквиума по физиологии» контекста нет.

**Реализация** (`workers/api/src/routes/ai.ts`):
1. Расширить корпус: физиология и химия уже дублируются в `histology_lectures` (upload-скрипты
   пишут туда же) — проверить и включить фильтр по `subject_slug` во всех предметах, а не только гистологию.
   Для предметов, где лекции живут в `site_content` (ключи `lectures`), добавить источник `payload`.
2. Сноски: prompt-инструкция «цитируй источник маркером [N]» + `metadata.sources` (уже возвращается)
   → фронтенд `/tutor` и `StudyAssistant` рисуют блок «Источники» под ответом, каждая сноска — ссылка
   на лекцию/фрагмент.
3. Режимы: «Точный» (RAG обязателен, temperature 0.2) / «Быстрый» (без RAG, temperature 0.5) —
   параметр в `POST /ai/chat` и селектор в UI.
4. Кнопка «Объяснить · ИИ» после неверного ответа в тесте (`src/components/physiology/PhysiologyTests.tsx`,
   `HistologyTests.tsx`, `tests/attempt`): шлёт в aiChat текст вопроса + выбранный + правильный ответ
   + subject_slug (RAG-контекст тянется из лекций предмета).

**Оценка:** 1–2 дня.

### 2.3. Интерактивные методички: конспект с пропусками (cloze) ⭐

**У Сеченова:** 5-шаговый урок — тема программы → текст методички → ключевые термины → пропуски →
мгновенная проверка → тест и повторение; «ошибки уходят в карточки SRS».

**Реализация:**
1. **Генерация**: worker `POST /lectures/cloze {lecture_id}` → берёт текст лекции (уже в БД),
   LLM выделяет 8–15 ключевых терминов → JSON `{items:[{before, answer, after, hint}]}`.
   Кэш в `site_content` ключе `cloze:<lecture_id>` (пересборка вручную/по версии лекции).
2. **UI**: страница `/lectures/[id]/learn` (или вкладка в лекции): текст с инпутами-пропусками,
   проверка по кнопке и «на лету», счёт заполнения, кнопка «Сбросить».
3. **Ошибки → SRS**: неправильно заполненные пропуски → `srs_cards` (source_type=`personal`,
   front=`подсказка/предложение`, back=`answer`) — уже поддерживаемая механика.
4. Прогресс прохождения — в `study_plans`-дни (если пропуск в плане дня — отметка done).

**Оценка:** 2–3 дня.

### 2.4. Лента активности (единая лента событий студента)

**У Сеченова:** «Открыл методичку → тест 7/10 → спросил тьютора → сел поздно → карточка повторения» —
всё падает в ленту, после каждого действия рекомендации пересобираются.

**Реализация:**
1. Таблица `activity_events` (user_id, kind, subject_slug, ref_id, payload jsonb, created_at;
   RLS owner-select, запись — только сервис-клиент). Индекс `(user_id, created_at desc)`.
2. Точки записи (по одной строке кода в каждом месте, service client):
   - завершение теста (`medbiohim_finish_test_attempt` → worker tests.ts после RPC);
   - открытие/дочитывание лекции (lectures API GET — лёгкое событие, дебаунс);
   - сообщение тьютору (ai.ts после сохранения);
   - SRS-review (srs.ts после review);
   - отметка ДЗ (planner/homework progress);
   - посещаемость/отработки (assignments PATCH).
3. Чистка: cron воркера раз в сутки удаляет старше 180 дней.
4. UI: блок «Недавно» в /study (последние 10 событий) + вход для рекомендаций и слабых мест.

**Оценка:** 1–2 дня (миграция + 6 точек + блок UI).

### 2.5. Конспект из чего угодно (запись/фото/PDF → конспект → карточки/тест)

**У Сеченова:** главная фича лендинга: «Запись, фото, PDF — любая лекция» → конспект с пропусками,
тестом и карточками, презентация и подкаст.

**Реализация (поэтапно):**
1. **MVP «фото/PDF → конспект»**: загрузка файлов (storage `files` уже есть), Gemini-multimodal
   через Vercel-прокси (`/api/ai/gemini` принимает image_url) → структурный конспект (markdown) →
   сохранение как «личная лекция» (my-lectures уже существуют!) → кнопки «Сделать пак карточек»
   (card_pack ai-generate по тексту конспекта) и «Тест по конспекту» (quiz-блок).
2. **Расшифровка аудио**: Gemini/Whisper через тот же прокси; лимиты — как у Сеченова (N минут/месяц),
   счётчик в `user_preferences` или таблице квот.
3. **Подкаст/презентация** — отложить (TTS + слайды, отдельный большой модуль).

**Оценка:** MVP 3–4 дня; аудио +2; подкаст/презентация — отдельная фаза.

### 2.6. ИИ-агент к экзамену (ночная подготовка + «двойник»)

**У Сеченова:** список вопросов + дата → план по дням; агент ночью разбирает билеты на завтра,
утром отчёт «двойник сдал пробный экзамен».

**Реализация:**
1. Вход: пользователь выбирает тест/билет (уже есть: `tests`, билеты с вопросами) и дату экзамена →
   создаётся `study_plans` с kind=`exam_agent` + списком вопросов.
2. Cron воркера (существующий `scheduled`, добавить ветку): каждую ночь для активных планов —
   генерация разборов вопросов на завтра (вопрос + эталонный ответ из банка + краткая выжимка LLM)
   в `study_plan_items`.
3. Утром: Telegram-бот (уже есть) шлёт отчёт: «на сегодня билеты 21–25, готово X из Y,
   пробный результат двойника 7/10» (пробный = LLM отвечает на вопросы так, как ответил бы студент
   по его профилю слабых тем — упрощённо: имитация ошибок по mastery тем).
4. UI: страница «Агент» в /study (список планов агента, прогресс, отчёты).

**Оценка:** 4–5 дней (cron + отчёты + бот-интеграция).

### 2.7. Ответы к экзамену (.docx)

**У Сеченова:** до 300 вопросов → документ с развёрнутыми ответами из методичек и ссылками.

**Реализация:** worker `POST /exam-answers/generate {test_id}` → берёт опубликованные вопросы
билета + ответы банка (+RAG-дополнение по лекциям) → генерация .docx библиотекой `docx`
(проверить, есть ли в deps воркера; если нет — генерация HTML→docx через simple template или
отдача markdown, конвертация на фронте). Выдача через files storage. Лимит: 1 генерация/день.

**Оценка:** 1–2 дня.

### 2.8. Устный экзамен голосом

**У Сеченова:** отвечаешь вслух → уточняющие вопросы экзаменатора → оценка.

**Реализация:** Web Speech API (`webkitSpeechRecognition`, ru-RU) на фронте (Chrome/Android;
Safari — ограниченно, fallback «напишите ответ») → текст ответа студента → LLM сравнивает с
эталоном вопроса банка (критерии: полнота, точность, термины) → балл 0–10 + уточняющий вопрос.
UI в `/tests/preparation` как отдельный режим. **Оценка:** 2–3 дня.

### 2.9. Лёгкие ИИ-инструменты (мнемоники, доска, «как пятилетнему»)

Кнопки-действия в тьюторе и лекции: «Мнемоника по теме» (aiChat), «Объясни как на экзамене /
как пятилетнему / как сплетню», «Схема на доске» → mermaid (рендер уже есть в лекторе).
**Оценка:** 0.5–1 день на все три (промпты + кнопки).

### 2.10. Геймификация (лиги, рейтинг)

Стрик уже есть в /cards. Лиги/глобальный рейтинг — соц-модуль (таблица недельных итогов,
RLS read-all, анти-чит по событиям activity_events). **Отложить** до стабильности ядра.

план по дням → лекции/тесты/паки со сносками тьютора → cloze → карточки с сжатыми повторениями.

---

## 5. Технические заметки

- **Лимиты ИИ**: у Сеченова 30 сообщений/час — у нас rate limit `/ai/chat` уже 30/300с; для
  генераций (cloze, паки, агент) — отдельные квоты на пользователя в день (таблица или счётчик в Redis).
- **Стоимость**: правило-каскад как в TodayPlan (правила дают каркас, LLM — текст) должен быть
  дефолтом; LLM-проходы кэшируются (site_content/таблицы), перегенерация — вручную.
- **RLS**: все новые таблицы owner-only; запись событий активности — только service client
  (паттерн `createServiceClient`).
- **Cron**: существующий scheduled в воркере расширяется веткой агента; идемпотентность по
  `(plan_id, date)`.
- **Не читать .env в клиенте**: все ключи уже на воркере/прокси.
- **Пулер БД**: при пакетных вставках — чанки по 25 строк (паттерн card-packs).
- Миграции — через `apply_migration` + файл-копия в `database/migrations/`.
