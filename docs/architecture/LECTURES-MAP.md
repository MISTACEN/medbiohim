# Лекции: где что лежит и где это видно

Короткая карта, чтобы не искать лекции «по всему сайту». В системе **три независимых хранилища** и **три поверхности**; дублей между ними нет, но и автоматической синхронизации тоже нет.

## Хранилища

| Хранилище | Путь | Кто пишет | Кто читает |
|---|---|---|---|
| Кафедральные и опубликованные лекции | таблица `histology_lectures` (Supabase) | миграции `database/migrations/*lecture*.sql`; админка (CMS) через `POST /admin/lectures/:id/publish` | `GET /lectures` → страница `/lectures`, страница `/lectures/[id]` |
| Черновики и авторские лекции | `site_content`, ключ `lectures` (`payload.items`) | админка `/admin/lectures`, `POST /admin/lectures/generate` | `GET /admin/lectures`, `GET /lectures/:id` (свои и опубликованные), cloze/подкаст/слайды |
| Архивные конспекты (статика) | `public/content/portals/lectures-{bio,math,chem,chem-organic,phys,latin,english,history}.json` | скрипты `scripts/build-*.mjs` и ручные правки JSON | вкладка «Портал» на странице предмета (`ArchiveLectures`), `/latin`, `/english` |

Связка между первым и вторым: при публикации админка пишет лекцию в `histology_lectures` (`syncPublishedLecture` в `workers/api/src/lib/lecture-quality.ts`). Обратной синхронизации нет: правка `histology_lectures` в БД не меняет `site_content`.

## Поверхности (что видит студент)

1. **`/lectures`** — список опубликованных лекций из `histology_lectures`, сгруппированный по предметам и подмодулям, с задачами и прогрессом. Отсюда открывается `/lectures/[id]` (текст, конспект с пропусками, шпаргалка, подкаст, слайды).
2. **Страница предмета → вкладка «Портал»** — архивные конспекты из JSON (`ArchiveLectures`). Это другой контент: HTML-конспекты курса, без задач и прогресса. Под заголовком есть ссылка на `/lectures`.
3. **`/search`** — полнотекстовый поиск **только по архиву**: `public/content/lectures-search-index.json` собирается из тех же JSON скриптом `scripts/build-lectures-search-index.mjs` (99 конспектов). Лекции из БД в этот индекс не попадают.

## Дубли и почему их «видно»

Изначально на вкладке «Портал» для химии рендерились **две карточки**: `setId="chem"` (8 конспектов) и `setId="chem-organic"` (14). Каждая — со своим заголовком и своим поиском, на одной вкладке. Это не дубли записей (id и названия уникальны), а две параллельные библиотеки в одном месте.

Сейчас `ArchiveLectures` принимает `sets={[...]}` и показывает **одну** ленту: слияние по `id`, затем по нормализованному названию, один заголовок, один поиск.

Отдельно: `LEGACY_PORTALS` в `src/lib/portalContent.ts` отдаёт одни и те же конспекты двум предметам — `chemistry_organic_physical` и `organic_chemistry` (канонический slug и исторический алиас). Это осознанно: у предмета два входа, контент один.

## Инварианты (проверяются тестом)

`test/lectures-content.test.mjs`:

- каждый набор из `LEGACY_PORTALS` существует и не пуст;
- внутри набора нет повторяющихся `id` и названий;
- между наборами нет повторяющихся `id`;
- объединённая лента химии не содержит дублей;
- `lectures-search-index.json` покрывает ровно все наборы: сверяются id (`setId:item.id`),
  `setId` и `count`, а не только количество записей (иначе пересоберите скрипт);
- нет «осиротевших» `lectures-*.json`, не подключённых к `LEGACY_PORTALS`.

### Пересечение «БД-каталог гистологии ↔ архив JSON»

Точных совпадений названий — **0**. Тематические пересечения (это **не дубли**: разные
предметы и разные поверхности, но студент видит одинаковые темы в двух местах):

| Тема | Гистология (`/lectures`, таблица) | Биология (вкладка «Портал») |
|---|---|---|
| Цитология | `lec-hist-cytology` «Цитология» | `bio:bio-cytology`, `bio:bio-cytology-cell` |
| Эмбриология | `lec-hist-embryology` «Общая эмбриология и эмбриогенез» | `bio:bio-embryology` |

Остальные «совпадения по словам» — ложные (`системы`, `производные`) и дублями не являются.
Где искать: гистология/цитология и эмбриология кафедрального курса → `/lectures`;
конспекты по биологии → страница предмета «Биология», вкладка «Портал».

### Что этим НЕ проверено

Живая база не запрашивалась (нет окружения и ключей). Неизвестны: фактическое число строк
`histology_lectures`, флаг `is_published`, заглушки и дубли **внутри** таблицы (миграции —
это намерение, а не состояние), расхождение `site_content:lectures` с таблицей. Для этого
есть `node scripts/audit-lecture-catalog.mjs` (нужен `.env.local`; `--fix` снимает с
публикации заглушки и дубли, `--sync` переносит опубликованное из редактора в каталог).
Страницы в браузере не открывались: слияние лент проверено тестом и кодом, но глазами не смотрено.

## Куда добавлять новую лекцию

- Кафедральная, с задачами и прогрессом → миграция в `database/migrations` или CMS → публикация (попадёт в `/lectures`).
- Авторский черновик → админка `/admin/lectures` (живёт в `site_content`, виден автору сразу, студентам — после публикации).
- Архивный конспект по предмету → JSON в `public/content/portals/` + прогон `scripts/build-lectures-search-index.mjs` (иначе он не найдётся через `/search`).
