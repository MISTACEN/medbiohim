# MEDBIOHIM — архитектура необязательного AI-кластера

## Зафиксированные решения пользователя

1. Кластер запускается **только вручную по прямой команде пользователя**. Автоматически превращать одиночную задачу в кластерную запрещено.
2. Одиночное использование любого приложения должно работать независимо от координатора, Bridge, MCP, Redis и доступности других компьютеров.
3. Координатор — необязательная надстройка для распределения задач, а не обязательный proxy/provider gateway.
4. У каждого ПК с ZCode отдельная запись исполнителя и отдельный учёт GLM-токенов. Не объединять лимиты двух ПК без подтверждения, что аккаунт/квота общие.
5. В ZCode используется собственная GLM-модель с утренним начислением токенов. **DeepSeek в ZCode не используется**; не назначать ZCode DeepSeek-модели и не учитывать там DeepSeek-часы.
6. Приоритет ресурсов: бесплатные лимиты и уже доступные подписки; платные API — только после отдельного разрешения и в пределах явно заданного бюджета.
7. Все агенты и субагенты во всех режимах получают непересекающиеся workstream, deliverables и writable ownership. Общие файлы имеют одного владельца и изменяются последовательно.

## Режимы работы

### Standalone (режим по умолчанию)
- Пользователь запускает Qoder, ZCode, OpenCode, DeepSeek Harness или Freebuff напрямую.
- Приложение общается со своим провайдером штатным способом.
- Координатор не перехватывает запросы, не меняет endpoint, model config, credentials или proxy.
- Bridge/Coordinator могут быть выключены или недоступны; это не должно мешать приложению.
- Никакие лимиты не резервируются и не блокируются кластером при обычной одиночной работе.

### Cluster (только ручной запуск)
- Пользователь явно выбирает «Запустить кластер» и передаёт задачу координатору.
- Координатор проверяет доступность устройств, лимиты, ownership и разрешённые действия.
- Задача делится на независимые workstream; каждому исполнителю назначаются отдельные файлы/ресурсы и deliverable.
- Результаты собираются, проверяются и интегрируются координатором последовательно в `main`.
- Если кластер остановлен или Bridge недоступен, standalone-приложения продолжают работать.

## Исполнители и учёт ресурсов

| Исполнитель | Ресурс/модель | Учёт |
|---|---|---|
| Qoder | Бесплатный Qwen 3.8 (по данным пользователя) | Отдельная квота Qoder; способ чтения остатка подтвердить через CLI/GUI |
| ZCode PC 1 | Собственная GLM-модель, утреннее начисление токенов | Отдельный quota account для ПК 1 |
| ZCode PC 2 | Собственная GLM-модель, утреннее начисление токенов | Отдельный quota account для ПК 2 |
| OpenCode | Бесплатный DeepSeek до исчерпания дневного лимита | Учитывать по фактическому источнику/аккаунту OpenCode |
| DeepSeek Harness | Бесплатные API-ключи, часть лимитов уже израсходована | Отслеживать каждый ключ отдельно, если провайдер даёт достоверные данные |
| Freebuff | Не инвентаризирован | Не назначать задачи до выяснения доступных моделей и интерфейсов |

Не предполагать, что остатки квот можно прочитать у каждого приложения. Каждое значение хранит источник и достоверность: `verified`, `estimated`, `manual`, `unknown`. Неизвестный остаток не трактуется как бесконечный.

## Архитектурные компоненты

- **Coordinator API** — принимает только явно запущенные кластерные задачи.
- **Quota Monitor** — хранит snapshots лимитов, время обновления, источник и уверенность.
- **Task Scheduler** — выбирает исполнителя с учётом пригодности, доступности, бесплатного остатка и времени сброса.
- **Ownership Manager** — запрещает пересекающиеся writable paths/resources.
- **Local Bridge** — отдельный агент на каждом ПК; исходящее защищённое соединение, heartbeat, CLI/GUI adapters и получение кластерных заданий.
- **MCP Server** — дополнительный интерфейс для MCP-совместимых приложений, не обязательный для standalone.
- **GitHub integration** — передача patches/artifacts; только координатор интегрирует их последовательно в `main`.
- **Supabase** — долговременные метаданные, устройства, исполнители, задачи, ownership и quota history.
- **Redis** — временные очереди, heartbeat и короткие leases; его отсутствие не влияет на standalone.
- **LiteLLM (опционально)** — только API-часть, если она действительно нужна; не проксировать через него подписочные приложения без явного решения пользователя.

## Обязательные ограничения

- Не менять конфигурацию, endpoint, ключи или авторизацию локальных приложений ради подключения к кластеру.
- Не читать/передавать секреты, cookies, токены сессий и приватные файлы.
- Не расходовать платные API по умолчанию; бюджет по умолчанию 0.
- GUI automation только по allowlist приложений и действий, с возможностью остановки пользователем.
- Кластер не имеет права изменять production API, Supabase schema/RLS, secrets, Worker bindings, DNS, storage или выполнять deploy без отдельного разрешения.
- Если адаптер не умеет надёжно получать квоту, показывать «неизвестно»/«оценка», а не придумывать точные цифры.
- Сбой Coordinator/Bridge/MCP не должен ломать одиночный запуск приложений.

## Приёмочные испытания

1. Отключить Coordinator и Bridge: все приложения по отдельности продолжают запускаться и работать.
2. Запустить кластер вручную: только после явной команды появляется кластерная задача.
3. Проверить два ZCode как два независимых устройства с раздельным GLM-учётом.
4. Убедиться, что ZCode не получает DeepSeek assignments.
5. Проверить, что неизвестные лимиты маркируются, а платный API не вызывается при бюджете 0.
6. Проверить отсутствие пересечений writable ownership и последовательную интеграцию patches в `main`.
