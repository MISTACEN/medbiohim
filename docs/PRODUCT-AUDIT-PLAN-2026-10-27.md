## 1. Резюме — главное

**Админка (20 страниц, 21 ссылка).**
1. 🔴 Ни одна страница `/admin/*` не проверяет роль — везде только `hasToken()` (`admin/page.tsx:42`). Студент видит всю CMS-навигацию, плитки и получает 403-баннеры по каждому запросу. Серверный guard есть только в Worker (`admin.ts:14-44`), `src/middleware.ts` отсутствует, роль на клиенте не проверяется нигде.
2. 🔴 Неверный счётчик пользователей: дашборд берёт `items.length` от `adminListUsers()`, который ограничен 100 (`admin.ts:346`) — при >100 студентов цифра занижена.
3. 🧟 Готовые API без UI: аудит изменений + rollback (`adminDbAudit`/`adminRollbackAudit`; бэкенд `admin-parity.ts:524-563`), `admin/content/move`, целый модуль версий/аналитики расписания (`admin-schedule.ts:46-288`). Панель версий/отката — самый дешёвый крупный выигрыш.
4. 🟠 Потеря труда без предупреждения: ноль `beforeunload` во всей `/admin` — несохранённая сетка расписания, черновик аттестации, SQL-окно исчезают молча; автосохранения в RichLectureEditor (867 строк) нет.
5. 🟡 Контент-разделы без пагинации/поиска: test-questions (1000 строк), tests (5000 вопросов), lectures, announcements; объявления нельзя отредактировать, `pinned` не управим, хотя API умеет.
6. SQL-консоль (745 строк) допускает произвольный SQL и удаление любых строк прод-БД; подтверждение есть, но истории действий в UI нет — при готовом audit API.

**Аккаунт-зона (настройки + вход).**
7. 🔴 Смена пароля не проверяет текущий пароль и не разлогинивает другие устройства (`settings/page.tsx:91-100`, `settings.ts:238-258`): владение устройством = полный контроль над аккаунтом.
8. 🔴 Чекбоксы уведомлений — пустышки: `notify_homework/notify_lectures/notify_email/media_prefer_ru` пишутся в preferences, потребителей в src и workers нет. «Язык: русский» — статичная строка.
9. 🟠 Смена email молчит о pending-подтверждении («Профиль сохранён» в любом случае); в UX утекли операторские тексты Supabase («Включите Auto Confirm», «URL Configuration»).
10. ❌ Нет: аватара (API готово!), списка активных сессий/«выйти везде», 2FA, экспорта данных, удаления аккаунта; история входов читается воркером (`settings.ts:59`), не рендерится.

**Пользовательские модули — 6 подтверждённых поломок (§ 5.1).**
11. 🔴 Поиск: фильтры типа сломаны — UI шлёт `question/ticket/trainer/subject/plan`, API принимает только `all/questions/lectures/materials` → 422 на любой фильтр, лекции ищутся только по title.
12. 🔴 Сообщество: сервер игнорирует `group_id` (UI его передаёт) — фильтр по группе мёртв.
13. 🔴 AI-тьютор: выбор Groq/Mistral/OpenRouter в UI молча сбрасывается (constraint БД на `auto/gemini/gigachat`); «Спросить тьютора» из поиска не работает (tutor_prefill пишется, но не читается).
14. 🟠 Оценки преподавателя за ДЗ (`grade/teacher_comment`) хранятся и возвращаются бэкендом, но нигде не показываются студенту.

**Пробелы платформы.**
15. ❌ Ноль уведомлений вообще ни по одному каналу (нет cron-хэндлеров вовсе), нет .ics-экспорта календаря, нет PWA, нет стриков; streak в SRS живёт только в сессии браузера.
16. 🟡 «Задания» — не раздел: `/homework` redirect на `/schedule` (849 строк); посещаемость — самоотчёт студента без подтверждения преподавателя.
17. 🟡 Живое ядро сильное: расписание (4 вида + attendance + ДЗ из карточки), TestsHub (4 режима, серверные попытки, AI-review), SRS, гистология-тренажёр с записью ответов, университет E2E через расширение, тьютор с историей. Данных много — но почти всё не используется в UI (оценки ДЗ, time_ms ответов тренажёров, time_limit_sec тестов, atlas-accuracy).

**Объём:** админка ≈ 13–18 д; аккаунт-зона ≈ 14–19 д; поломки ≈ 7,5–9,5 д; функциональные улучшения и «сквозные» (уведомления, .ics, PWA) ≈ 21–28,5 д. Итого **≈ 55–75 д**, без химии и части 1.

## 6. Сводный порядок работ

```
Неделя 1    MA1 (роль-гейт), MA2 (счётчик), SA1 (пароль), SA9 (чистка UX), FD1 (поиск)   ← безопасность + дешёвые быстрые победы

Недели 6-7  SA4 (сессии), FA3 (прогресс v2), FA4 (/homework), MA5, MA8, MA9, FD5-FD8
Недели 8+   FA5-FA12, SA6-SA10, MA10-MA13 — по приоритетам продукта
```

**Правила порядка:**
- MA1 и SA1 — до любых новых фич: это безопасность, а не полировка.
- Не начинать уведомления, пока не решено «подключаем чекбоксы или убираем» (SA5): пустышка хуже отсутствия.
- MA4 (DataTable) писать до контент-разделов, чтобы не переделывать.
- Сверяться с частью 1: волны типов/CI/дизайн-токенов идут параллельно и не конфликтуют по файлам (пересечение только на `.badge-*` — они понадобятся MA6/FA1).

- Не превращать сообщество в мессенджер: комментарии в 1 уровень достаточно.
- Не удалять SpaceWeb-пресеты/legacy-бэки из воркера до появления UI-аудита (MA3) — это страховка миграции.
- Не добавлять i18n-каркас «про запас» — весь студенческий контент русскоязычный.
